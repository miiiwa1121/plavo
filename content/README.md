## セリフの規則

すべてのセリフは以下を満たす。`server` の `npm run check:dialogues` で機械的に検証できる。

検出は2段階に分かれる。

**違反（必ず直す）**

| 規則 | 根拠 |
|---|---|
| 一人称代名詞（ぼく・わたし・おれ 等）を使わない | D31 |
| 40字以内 | 設計 |
| 計測値を言わない（%・℃・ルクス等） | 原則2 |
| 絵文字・顔文字を使わない | 設計 |
| ユーザーを責めない | D30 |
| ユーザーに命令しない（ください・ましょう 等） | 設計 |

**警告（人が判断する）**

| 規則 | 理由 |
|---|---|
| ユーザーへの依頼（もらえる・てほしい 等） | 丁寧な依頼は命令ほど強くない。文脈によっては許容できる |
| 行動をうながす呼びかけ（見て・チェックして） | 同上 |

警告では検証を失敗させない。人の判断を要するものを機械で止めるべきではない。

## 選び方

同じ帯域の中からランダムに1本選ぶ。ただし**直前に出したものは除外する**。来場者の滞在は数分なので、この程度で繰り返しは避けられる（D34）。

## レビュー待ちのセリフ

`npm run check:dialogues` が検出した、判断が必要な行。**メンバーのレビュー対象。**

### 違反 1件 — 設計と明確に衝突する

| セリフ | 問題 | 根拠 |
|---|---|---|
| 「ねえ、お水のこと忘れてない？」 | **ユーザーを責めている** | D30。植物はユーザーを責めない。「水をくれなかったから」と同じ構造 |

代案として「今日はまだお水もらってないよ」（事実の申告に留める）が同じ帯域に既にある。

### 警告 5件 — 人が判断する

いずれも「植物は自分の状態を言うだけで、ユーザーに指示しない」という設計意図（D30）と衝突しうる。ただし丁寧な依頼は命令ほど強くなく、**文脈によっては許容できる**。

| セリフ | 引っかかった点 | 状態の表明に寄せた代案 |
|---|---|---|
| 「そろそろお水ほしいな」 | 依頼（ほしいな） | 「そろそろお水がいるかも」 |
| 「もう少しだけ、お水もらえる？」 | 依頼（もらえる） | 「もう少しだけ、足りない」 |
| 「見て見て、ここ！」 | 呼びかけ | 「ここ、変わったんだ」 |
| 「少し様子を見てもらえる？」 | 依頼＋呼びかけ | 「なんだか調子が違う気がする」 |
| 「葉っぱをチェックしてほしいな」 | 依頼＋呼びかけ | 「葉っぱの様子が、いつもと違う」 |

**判断の軸**: 植物が「お願いする」と、ユーザーは指示を受けた側になる。植物が「困っている」と言うだけなら、ユーザーは自分で気づいて動く。**後者のほうが、気持ちが伝わったという体験になる。**

ただし展示は数分の接触なので、明示的な依頼のほうが伝わりやすいという判断もありうる。**この5本は残すか置き換えるかを決めてほしい。**
