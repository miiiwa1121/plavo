| 項目 | 現状 |
|---|---|
| Xcode | 26.6 |
| 署名ID | `Apple Development: tsubasa.m1121@icloud.com (4PM8SZR33W)` |

### 端末による違い

| 項目 | iPhone 17 | iPhone 11 |
|---|---|---|
| ARKit ワールドトラッキング（6DoF） | 対応 | **対応**（A13） |
| 画像トラッキング | 対応 | 対応 |
| LiDAR | 機種による | 非搭載 |
| 前景マスクによる検出 | 速い | **遅い** |

**LiDAR は必須にしていない**（D3-a）。レイキャストが外れたら固定距離に置くフォールバックがあるため、両端末で動く。

**検出の速さには差がある。**前景マスクの処理は A13 では新しいチップより重い。固定間隔にすると遅い端末で描画を圧迫するため、**実測に応じて検出間隔を伸ばす**実装にしている（0.4〜2.0秒）。検出の頻度を落としてでも描画のフレームレートを守る。

**iPhone 17 で問題なくても、iPhone 11 では別途確認が必要。**展示で使うのは iPhone 11 のほう。

## 2. 手順

**上から順に実行する。順序に意味がある。**特にデベロッパモードは、Xcode から実行を試みるまで iPhone の設定に項目が現れない。

### 2-1. プロジェクトを生成して開く

`.xcodeproj` は `project.yml` からの生成物なので、リポジトリには入っていない。

```bash
cd ios/PlavoApp
xcodegen generate
open PlavoApp.xcodeproj
```

`xcodegen` が無ければ `brew install xcodegen`。

### 2-2. 署名を設定する

**これを先にやる。**署名が未設定だとビルドが通らず、次のデベロッパモードのエラーにすら到達しない。

1. 左のファイル一覧の**一番上にある青いアイコンの `PlavoApp`** をクリックする
2. 中央に設定画面が出る。左側の **TARGETS → PlavoApp** を選ぶ
3. 上部のタブから **Signing & Capabilities** を開く
4. **Automatically manage signing** にチェックを入れる
5. **Team** で自分の Apple ID を選ぶ

Bundle Identifier が `dev.plavo.PlavoApp` のままで衝突する場合は、末尾に何か足して一意にする。

### 2-3. 実機を接続して、実行先に選ぶ

1. iPhone を Mac に USB で繋ぐ
2. iPhone に「このコンピュータを信頼しますか」と出る → **信頼**（パスコード入力）
3. Xcode の**上部中央**に `PlavoApp` と `iPhone 17 Pro`（シミュレータ名）が横に並んでいる。この**右側（実行先）をクリック**する
4. 開いた一覧から、接続した実機を選ぶ。実機はシミュレータより上に出る

実機が一覧に出ないときは、ケーブルの接続と、手順2の「信頼」を確認する。**Window → Devices and Simulators** で状態を見られる。

### 2-4. デベロッパモードを有効にする（iOS 16以降・必須）

**端末を移行しても引き継がれない。**デベロッパモードは端末ごとの設定で、バックアップ復元の対象外。新しい端末では改めて有効にする。

1. Xcode で **⌘R** を押す → `Developer Mode disabled` というエラーが出る
   - **このエラーを出すことが目的。**これで iPhone 側に設定項目が現れる
2. iPhone: **設定 → プライバシーとセキュリティ → デベロッパモード**
3. オンにする → 再起動を求められる → **再起動**
4. 再起動後にダイアログが出る → **オンにする**（パスコード入力）

初回接続時、Xcode が「Preparing device for development」と表示してシンボルをコピーする。**数分かかるが正常。**

### 2-5. 実行する

Xcode で **⌘R**。

### 2-6. デベロッパを信頼する（無料アカウントの場合）

初回起動時に「信頼されていないデベロッパ」と出たら、iPhone の **設定 → 一般 → VPNとデバイス管理 → デベロッパApp** から、自分の Apple ID を**信頼**する。

### 2-7. カメラを許可する

起動して**カメラ**タブを開くと許可を聞かれる。許可しないと AR が動かない。

## 3. 実機で確認すること

**ここが今回の最大の未検証領域。**優先度順に並べる。

### 診断表示の出し方

**カメラタブの下部を1.5秒長押しする**と、モック操作と一緒に AR の診断が出る。吹き出しが出ないとき、どこで失敗したのかを切り分けられる。

| 項目 | 見方 |
|---|---|
| **映像** | 選ばれた映像形式（解像度とフレームレート）と HDR の有無。**画質の確認に使う** |
| **撮影** | 撮れる静止画の大きさ。1枚撮ると実測値に変わる |
| **画質** | 撮影 / 映像 / 標準の切り替え。既定は「撮影」。高解像度は検出とトラッキングの負荷を上げるため、追従がカクつくなら「標準」に落とす |
| トラッキング | 「制限中（特徴が足りない）」なら環境が暗いか無地すぎる。**正常になるまで検出は走らない** |
| 特徴点 | 少ないと奥行きが取れず、追従も不安定になる。目安として100以上 |
| 検出 | `成功/試行 回` と処理時間、現在の間隔 |
| **植物らしさ** | 分類から求めたスコアと、現在のしきい値。**これがしきい値を超えないと吹き出しは出ない** |
| 対象 | いま何を見ていると判定しているか（なし / 植物 / パネル） |
| 奥行き | 「レイキャスト」なら特徴点に当たっている。「固定(1.2m)」はフォールバック（D3-a） |
| 距離 | アンカーまでの距離 |
| 吹き出し | 画面座標。「画面外」ならアンカーはあるが投影の外にある |
| **分類** | Vision の分類器が返した上位のラベルと確度。**どんな語で返ってくるかを見て、しきい値を調整する** |

### 植物の判定としきい値の調整

**前景マスクは「主要被写体」の位置を返すだけで、それが植物かどうかを見ていない。**そのため分類（`VNClassifyImageRequest`）を挟み、植物を表すラベルの確度を合計して判定している。

診断パネルの一番下に**しきい値のスライダー**がある。実際の植物に向けながら調整する。

| 症状 | 対処 |
|---|---|
| 何もないのに吹き出しが出る | しきい値を上げる |
| 植物に向けても出ない | 「分類」に出ているラベルを確認する。植物を表す語が出ているのに拾えていなければ、`SceneController.plantKeywords` に語を足す |

**「分類」に出た語を報告してもらえれば、キーワードの一覧を調整できる。**

**再検出**ボタンでアンカーを捨てて、もう一度検出からやり直せる。繰り返し試すときに使う。

**iPhone 11 での検証では「検出」の処理時間を必ず見る。**間隔が自動で伸びるので、そこに端末性能が現れる。

**画質を上げると検出は遅くなる。**映像の解像度がそのまま Vision の処理量になるため。「最高」で検出が遅すぎるなら「標準」に落とし、両方の数字を比べる。

### 優先度 高 — これが動かないと展示が成立しない

| # | 確認内容 | 見るところ |
|---|---|---|
| 1 | **植物を検出できるか** | 鉢植えにカメラを向けて、吹き出しが出るか。出るまでの秒数 |
| 2 | **吹き出しが空間に留まるか** | 端末を左右に振る。吹き出しが画面端から消え、戻すと同じ場所に現れるか |
| 3 | **吹き出しが飛ばないか** | 震える・明後日の方向へ飛ぶ・地面にめり込む、が起きないか |
| 4 | **奥行きが妥当か** | 植物の少し上に浮いて見えるか。壁にめり込んだり、手前で巨大化したりしないか |

### 優先度 中 — 体験の質に効く

| # | 確認内容 | 見るところ |
|---|---|---|
| 5 | フレームレート | 吹き出しの追従がカクつかないか。30fps を割っていないか |
| 5-a | **映像の画質** | カメラアプリと見比べる。「撮影」「映像」「標準」を切り替えて差を見る |
| 5-b | **撮った写真の画質** | シャッターを押し、日記に入った写真をカメラアプリの写真と見比べる。診断の「撮影」に実測の解像度が出る |
| 6 | 検出の誤り | 植物以外（机、人、壁）に反応してしまわないか |
| 7 | 発熱 | 10分連続で使って、熱で処理が落ちないか |
| 8 | バッテリー | 10分でどれくらい減るか |

**5〜8 は iPhone 11 でも必ず確認する。**展示で使うのは iPhone 11 のほうであり、iPhone 17 で問題なくても A13 では厳しい可能性がある。

### 優先度 低 — 環境依存

| # | 確認内容 | 見るところ |
|---|---|---|
| 9 | 暗い場所での挙動 | 展示会場の照明は特殊なことが多い |
| 10 | 逆光での挙動 | 窓際など |

### まだ確認できないこと

**パネルの画像トラッキング（時系列の再生）は、印刷したパネルが無いと確認できない。**パネルができたら AR Resource Group「PanelImages」に登録する（§5）。

## 4. うまくいかないとき

| 症状 | 原因と対処 |
|---|---|
| `Signing for "PlavoApp" requires a development team` | §2-2 の Team が未設定 |
| `Unable to install` | iPhone のロックを解除して、信頼の確認に答える |
| 起動直後に落ちる | 「信頼されていないデベロッパ」。§2-4 |
| 起動して7日後に落ちる | 無料アカウントの失効。入れ直す（§0） |
| カメラが真っ暗 | カメラの許可を拒否している。設定 → plavo → カメラ |
| 「ARはこの環境では動きません」と出る | シミュレータで実行している。実行先を実機に変える |
| `Developer Mode disabled` | デベロッパモードが無効。§1-a |
| デベロッパモードの項目が設定にない | まだ Xcode から実行を試みていない。§1-a の順序どおりに進める |
| iPhone 11 で吹き出しの追従がカクつく | 検出が描画を圧迫している。`SceneController` の `maxDetectionInterval` を上げる |
| 吹き出しが出ない | 診断表示（§3）で切り分ける。「植物らしさ」がしきい値を超えていなければ分類で弾かれている。「吹き出し 画面外」ならアンカーはあるので端末を動かす |
| 何もないのに吹き出しが出る | しきい値を上げる（§3の調整） |
| 吹き出しがぶれる | 平滑化を入れてあるが、まだ揺れるなら `SceneController.smoothing` を下げる（0に近いほど強く効く） |
| アプリを開いた瞬間に吹き出しが出る | トラッキングが正常になるまで検出しない実装になっている。それでも出るなら誤検出なのでしきい値を上げる |

## 5. パネル画像の登録（パネルができてから）

時系列パネルの識別には ARKit の画像トラッキングを使う。

1. 印刷したパネルを**正面から**撮影する
2. Xcode で **Assets.xcassets → 右クリック → New AR Resource Group** を作り、名前を `PanelImages` にする
3. 撮影した画像をドラッグして入れる
4. 各画像の **Name** を `content/dialogues/timeline.json` の `panels[].key` と一致させる

| 画像の Name | 対応するパネル |
|---|---|
| `sprout` | 6日目・発芽 |
| `trueLeaf-early` | 14日目・本葉が出た |
| `trueLeaf-thirsty` | 23日目・水切れ |
| `trueLeaf-recovered` | 24日目・水やりの翌日 |
| `bud` | 38日目・つぼみ |
| `bloom` | 45日目・開花 |
| `seedSet` | 62日目・結実 |
| `withered` | 78日目・枯死 |

各画像に **Physical Size**（実際の印刷サイズ）を必ず設定する。これが吹き出しの位置と大きさの計算に使われる。

**パネルはマット紙・非光沢で印刷する。**光沢があると照明を反射し、認識精度が落ちる。

| 操作 | 場所 | 内容 |
