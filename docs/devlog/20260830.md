### 5. AR の実装方針を決めた

**吹き出しは RealityKit のエンティティではなく SwiftUI で描く。**位置だけワールド座標のアンカーから投影して求める。

この折衷を選んだ理由:

- 位置は空間に固定される（D3 の要件を満たす）
- 文字の描画は SwiftUI のほうが圧倒的にきれいで、調整もしやすい
- `SpeechBubble` をセンサー画面と共有できる

植物の検出には `VNGenerateForegroundInstanceMaskRequest`（前景マスク）を使った。汎用の物体検出ではなく前景マスクにしたのは、鉢植えのように「画面の主役が1つだけある」場面で最も安定するため。

**パネルの識別には ARKit の画像トラッキングを使う。**パネルは事前に印刷した既知の画像なので、汎用の物体検出より遥かに正確で安定する。参照画像の名前を `timeline.json` のパネルキーと一致させる設計にした。

### 6. 見つけた問題

#### 型名の衝突

`PlavoCore.Observation` が Swift 標準の `Observation` モジュールを隠し、`@Observable` マクロの展開が壊れていた。

```
error: 'Observable' is not a member type of struct 'PlavoCore.Observation'
```

`PlantObservation` に改名した。**型名の付け方が悪かった。**ドメインの言葉をそのまま型名にすると、標準ライブラリと衝突することがある。

#### sed の単語境界が効いていなかった

改名に `sed -i '' 's/\bObservation\b/.../g'` を使ったが、**BSD版の sed は `\b` を解釈しない。**置換が一切適用されていなかった。しかもテストは通った——何も変わっていなかったから。

**「テストが通ったから直った」と判断しかけた。**ビルドエラーが同じ内容で再発したことで気づいた。Python の正規表現で置換し直した。

#### リソースがバンドルに入っていなかった

xcodegen の `resources:` でプロジェクト外のパスを指定したが効かず、バンドルに JSON が1つも入っていなかった。アプリは起動したが「セリフを読み込めませんでした」と表示された。

`sources` に `buildPhase: resources` と `type: folder` で指定し直して解決した。

**エラー画面が正しく出たことで、フォールバックの実装は検証できた。**想定外の形ではあったが。

#### 乾く速度が速すぎた

シミュレータで動かして初めて分かった。1.5%/秒だと**26秒で適正から危険域まで落ちる。**説明を聞いている間に植物が死にかける。

0.6%/秒に落とし、あわせて**セクション4は水切れ状態から始める**ようにした。D25 のデモは「水切れ→水やり→回復」なので、来場者が着いた時点で植物が水を求めている必要がある。設計に書いてあったのに、実装では初期値を中間の45%にしていた。

**画面を見るまで気づかなかった。**数値を眺めているだけでは、体験の速さは判断できない。

## 追記 — 一本道フローの撤回とタブ構成への差し戻し

### 判断の誤り

展示アプリを「4セクションの一本道フロー」として実装したが、**撤回した。**

> 展示でのフローとアプリ内の構造は関係ありません

指摘のとおりだった。展示の順序（説明 → AR → 時系列 → センサー）は**説明員と物理配置が担うもの**であり、アプリが強制するものではない。D13で決めたタブ構成に戻した。

**私は「製品版と展示版を分ける」という整理を D34・D36 で2回やっており、その型を機械的に3回目にも当てはめてしまった。**しかし前の2つ（AI呼び出し・永続化）は技術的な制約から来る分離で、今回は違う。展示のフローはそもそもアプリの責務ではなかった。同じ形に見えても、理由が違えば結論も違う。

### 差し戻した構成

```
TabView
├── カメラ        AR。向けた対象で振る舞いが変わる
├── マイプラント   育てている植物
├── 日記          時系列の記録
├── ルーム        枠のみ（G-02）
└── マイページ    リセット操作の置き場も兼ねる
```

起動時の既定はカメラ（D2）。

### 副産物 — AR の実装が1本にまとまった

セクションを分けていたときは `PlantAnchorController` と `PanelTrackingController` の2つがあり、それぞれ別の ARSession を持っていた。

タブ構成に戻したことで、**カメラタブ1つが「向けた対象によって振る舞いを変える」**という形になり、`SceneController` 1本に統合できた。

```
向けた対象
├── 登録済みのパネル → その日の記録を再生（AI診断は走らせない）
├── それ以外の植物   → センサーの状態に応じたセリフ
└── 何も見つからない → 「見当たらないなぁ」
```

`ARWorldTrackingConfiguration` は `detectionImages` を持てるため、1つのセッションで画像トラッキングと前景マスク検出の両方を扱える。**セッションを分けると切り替えのたびにトラッキングが初期化され、体験が途切れる。**構造を正したら実装も素直になった。

### 確認したこと

シミュレータでタブ構成と日記タブの表示を確認した。`timeline.json` のデータが時系列で並ぶ。カメラタブはシミュレータでは AR 非対応の表示になる（想定通り）。

起動引数を `-startSection` から `-startTab` に変更した。
