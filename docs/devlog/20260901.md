# 開発ログ 2026-09-01

サイドバー（左端の弧）の見た目を直した日。**まず部品の名前を決め、そのあとで材料の付け間違いを直した。**

## 名前が無いから直せなかった

サイドバーの UI 改善が数日にわたって進まなかった。原因のひとつは**呼び名**だった。「印」「塊」「弧」「バー」が場面ごとに混ざり、**どこの話をしているのかが会話とコードで食い違っていた。**

タブバーを手本にしているのだから、**対応する部品には対応する名前を付ける**ことにした（D41-b）。

| 呼び方 | タブバー（手本） | サイドバー |
|---|---|---|
| 全体枠 | バーそのもの | **通常円**（触っていないときの小さな半円）／**拡大円**（触っているときの大きな弧） |
| 囲い枠 | 選択中を囲う塊 | 名前を囲う塊 |
| 文字 | 項目名＋アイコン | 名前 |

コードの名前もこれに合わせた。

| 変更前 | 変更後 |
|---|---|
| `closedRadius` / `closedCenterX` | `restingRadius` / `restingCenterX` |
| `openRadius` / `openCenterX` | `expandedRadius` / `expandedCenterX` |
| `blob` / `blobVisual` / `blobSize` | `nameFrameShape` / `nameFrameVisual` / `nameFrameSize` |

`PlantSelectorArc` の冒頭に対応表を置いた。**次に触る人が、どの語がどの部品かを最初に読める場所**に置きたかった。

## 名前を決めたら、間違いが目で見えた

並べた瞬間に分かった。**材料が逆に付いていた。**

| | 変更前 | 変更後 |
|---|---|---|
| 全体枠（通常円・拡大円） | 明るさから作ったべた塗り | **Liquid Glass** |
| 囲い枠 | **Liquid Glass** | **べた塗り** |

タブバーでガラスなのは**バー本体**で、選択中を示しているのは無彩色の塗りひとつ。こちらは逆に付けていた。

**8/31 に「実機でガラスらしく見えない」として保留した残件は、たぶんこれが理由。**囲い枠はすでに全体枠の上に乗っているので、**そこにガラスを重ねてもぼかす先が無い。**ガラスは背景を取り込んで初めてガラスに見えるのに、取り込む背景として自分の下にある塗りしか無かった。

**「材料が効かない」ではなく「材料を置く場所が違った」。**同じ症状でも原因の階層が違うので、実機で見比べる前に机上で潰せた——名前を並べたからで、それが無ければまた実機に持っていっていた。

## 地の色を、白か黒のどちらかにした

タブバーは周りの明るさで**白い地と黒い地を切り替える**だけで、あいだを取らない。サイドバーは実測した明るさをそのまま色にしていたので、**連続的に変わっていた。**並ぶと別の作りに見える。

2状態にした。

| 状態 | 地 | 名前（選択外） | 囲い枠 |
|---|---|---|---|
| 暗い | 白 0.06 | 白 0.72 | 白 0.20 |
| 明るい | 白 0.92 | **黒 0.66** | 白 0.92 |

**切り替わる明るさは、入るときと出るときでずらした**（0.58 で明るいへ、0.42 で暗いへ）。境目がひとつだと、そこで明るさが揺れるたびに白黒が往復する。切り替わり自体は目に付くので、色だけ 0.28 秒かけて移す。

### 2状態にして初めて見えた不具合

**明るい場所で名前が読めなくなっていた。**地は連続的に白へ寄っていくのに、文字はずっと白のままだった。連続だと「だんだん薄くなる」だけなので、どこから読めないのかがはっきりせず、**不具合として認識できていなかった。**白か黒に振り切って初めて、白地に白文字が出た。

地が白へ回れば文字は黒へ回すようにした。タブバーがやっていることと同じ。

**中間を消すと、端が見える。**連続値は不具合を薄く塗り伸ばす。

## ガラスには色を掛けてある

Liquid Glass が AR の映像を取り込めるかは**まだ確認できていない**（8/31 の残件3）。`UIVisualEffectView` と `Material` は取り込めなかったが、Liquid Glass は別実装なので同じとは限らない。

**取り込めていない場合、無着色のガラスは明るくても暗くても同じ見え方になる。**そこで、実測した明るさから作った色を `.tint` として掛けてある。**どちらに転んでもタブバーと同じ明暗には付いてくる。**

## 追記 — 円の縁に白線が出た

実機で見ると、**円の縁に白い線が一本走っていた。**ガラスは形の輪郭に沿って明るい光沢を描く。タブバーではその線が枠の丸みに沿って一周するので馴染むが、**弧は片側しか見えないぶん、一本の線として目立つ。**

材料側に強さを直す設定は無い。**削る幅だけ大きく描いて、元の大きさで切る**ことにした。いちばん明るいところが切り取られた外側に落ち、内側の淡いところだけ残る。

**大きくするのはガラスだけで、弧の大きさは変えない。**頂点の位置（`apexX`）は頂点アイコンの置き場所と触れる範囲の基準になっているので、ここが動くと関係ない場所がずれる。

縁取りを重ねて隠す手も考えたが、**地が半透明なのでそこだけ濃くなる。**白線が濃い線に変わるだけで解決しない。

### 消しすぎていた

最初は 4pt 削って**光沢を丸ごと落とした。**これは行きすぎだった——**タブバーの全体枠にも同じ光沢がある。**無くすと、揃えるつもりが逆に材料の違いになる。

問題は「縁があること」ではなく「**弧では同じ縁が強く出ること**」だった。タブバーは枠を一周するので線ではなく丸みとして読めるが、弧は輪郭の片側しか見えないので一本の線になる。**同じ材料でも、形が違えば同じ強さにはならない。**

削る幅を、光沢が残る程度に下げた。

| 地 | 削る幅 |
|---|---|
| 暗い | 1.5pt。**白い光沢は黒地でいちばん際立つ** |
| 明るい | 0.5pt。地に紛れるので、ほとんど削らない |

**「消す」と「弱める」を取り違えていた。**指摘を受けるまで、手本のほうにも縁があることを確かめていなかった。

## 追記 — 左下の枠を、撮る前から置く

左下の直近の1枚は、**1枚も撮っていないあいだ何も出していなかった。**撮って初めて現れる。空の枠を先に置くことにした。

**行き先を、撮る前から見せる。**何も無いところに1枚目が現れる作りだと、撮ったものがどこへ行ったのかを**その瞬間に見ていないと分からない。**先に枠が見えていれば、撮ったあとはそこが埋まるだけになる。元々この部品は「撮ったものがどこへ行ったのか分からない」を直すために置いた（D42）のに、**1枚目のときだけその問題が残っていた。**

決めたことが2つ。

| | どうしたか | なぜ |
|---|---|---|
| 空の枠の地 | 暗い地を敷く（黒 0.25） | 線だけだと映像が枠の中を素通りして、空いている場所ではなく**映像に乗った線**に見える |
| 空の枠への操作 | 触れる先にしない | 開く1枚がまだ無い。**下端はシャッターを滑らせて切り替える帯でもある**ので、押せない物を置いて滑りを止めたくない |

置き場所（左下・シャッターと同じ高さ）と大きさは埋まっているときと同じにした。**枠が動かないから、そこが埋まったことだけが変化になる。**

### 読み違えた

最初「実撮影時」と読んで、**実機で枠が見えない**話だと解釈し、白い線が明るい景色に溶ける件を直した（白＋黒の2本）。誤字で、正しくは「未撮影時」。2本線は戻して白1本のままにしてある。
