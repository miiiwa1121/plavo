## 赤いセンサーの札をカメラで見つけて、枠に仮の値を出す（D64-a）

実機で plavo のカメラ画面を画面収録した動画を2本もらった（`reference/sensor_mock/モックあり.mp4`・`モックなし.mp4`）。動画の植物はパキラではないが、検出は植物を覚えないので問題ない。

### 色の範囲を動画で決める

- コマを5fpsで取り出し、カメラの映像の部分（上の株のアイコンと下のシャッター・タブバーを除く）だけを見た。画面収録の赤い録画マークは画面の表示で、アプリが見る AR の映像には入らないので外した
- 札の赤は鮮やかさの中央値が 0.9 前後、床・木・カーペットのピンクは 0.35 以下。**鮮やかさ 0.55 で切れば、くすんだ赤はほぼ落ちる**
- **詰まった点: 札なしの動画で、床のサンダルの赤いロゴが札と同じ色・同じ大きさで写った。**形（縦横比・詰まり具合）も札と変わらず、色と形では見分けられなかった。札は植物に付けるものなので、**植物の枠の近くの赤だけを数える**ことにした
- 検出の本体を PlavoCore に置き（`SensorTag.swift`）、**同じコードを Mac でコマに掛けて**数えた。植物の枠はアプリと同じ Vision の前景マスクで出した
  - 毎回の前景マスクの枠と比べると、腕や靴を拾った小さな枠で札を落とした（9コマ）。**最後に植物と認めた枠**（面積4%以上）と比べるようにして救った
  - 植物の枠を広げる余白は 0.05〜0.15 で札ありの結果が同じだった。鉢が前景の枠に入らない株に備えて 0.10 にした
  - 結果: 札ありはコマごとに 93%、枠に値が出ていた割合 97%、初めて出るまで 1.2 秒。札なしは 0%

### アプリに組み込む

- 札は**0.3秒おき**に探す。植物の検出は相手が決まったあと1.2秒おきで、そのままでは1回の取りこぼしで「2秒見失ったら消す」に掛かる。色を数えるだけなので軽い（映像を幅192に縮めてから走査する）
- 出し入れは `SensorTagTracker`（続けて1秒・2回以上で出し、2秒見失って消す）。**「1秒止まっている」は「1秒続けて見えている」で代えた。**端末そのものが手で動くので、画面上で止まっているかでは測れない。振り回すとぶれて見つからない
- 見つけたら右のつまみを緑にし、札の上に緑の丸い印を出す。札の画面上の位置は、カメラの映像が画面いっぱいに拡大して切り取られることを計算に入れて出す（既存の吹き出しの位置は近似のまま）
- 枠の中身は仮のデータ。土壌水分は説明員用の隠し操作と同じ値で、ほかは固定。枠の上は選ばれている株の名前と「センサー（赤）」
- 起動時の中継サーバーへの自動接続をやめた。D64 で足した「ガジェットの値が届き続けているか」（`SensorClient.isLive`）は使わなくなったので外した
- デモカメラ用に `-demoSensorTag YES` と `-demoTagBox` を足した。シミュレータで、つまみの色・印・枠の中身・札が無いときの「検出できません。」を確かめた
- Core Image で縮めた画像が上の行から書き出されることと、向きの指定が Vision と同じに効くことを、Mac で小さな画像を作って確かめてから組んだ

次にやること: 実機で確かめる（AR の映像からの検出は、シミュレータでは動かせない）。会場の照明でも一度見る。

### 実機で確かめてもらい、画面の端の赤での誤検出を直す

ユーザーが実機で確かめた結果:

- 札を付けると緑の印が出た。印は札にきちんと重なっていた。札を外すと消えた
- **画面の端に赤い物が少し映るだけで検出してしまう**

原因は2つあると考えた。

- **画面に映っていない部分まで探していた。**カメラの映像は 4:3 で、画面いっぱいに拡大して左右を切り落として映している。検出は切り落とす前の全体に掛けていたので、画面の外（縦持ちで左右あわせて約4割）の赤まで拾っていた。端に少し見えている赤い物は、大部分が画面の外にあり、検出には大きな赤の塊に見えていた
- 画面の端で切れている赤も数えていた

直し方:

- 札を探すのは画面に映っている範囲だけにした。植物の枠（画像全体の割合）は、切り出した範囲の割合に直してから比べる。返す枠は画面の割合なので、画面の大きさを掛ければそのまま印の位置になる
- 画面の端に接している塊は数えない（PlavoCore の `SensorTagDetector.edgeMargin`。テストを2件足した）
- 動画で測り直した。札ありは変わらず（93%・97%）、札なしで残っていた3コマ（右端のサンダル）も数えなくなった
- 切り出しの計算は、Mac で答えの分かっている画像（画面の外に大きな赤、画面の中に札）を作って確かめた。画面の外の赤は無視され、札は期待した位置から2pt以内で見つかった

### 「植物の近く」の判定を根本から見直す相談（実装はまだ）

> 根本的にセンサーが植物の近くにあることは検出できないの？

端の誤検出は減ったが、いまの「植物の近く」は植物を囲む**四角**で見ているので粗い。四角は植物より広く（葉のあいだの背景や、近づいたときは画面の大半が入る）、奥行きも見ておらず、少し前の四角を使っている。

案を3つ出した。

- A. 植物の切り抜き（前景マスク）そのものに**接しているか**で見る。おすすめ。データはもうある
- B. 札と植物の**奥行きの差**で見る。LiDAR のある機種なら確実
- C. 札の周りの色（緑）で見る。土に挿すと周りが土の色になり、使いにくい

ユーザーの回答: 展示の機種はいま確認できない。**札は植木鉢の土に挿す。**残っている誤検出の場面はまだ確認できていない。

進め方の案: A を、鉢に挿す前提で作る（切り抜きに鉢や土が入らない場合に備え、輪郭の**下側にだけ**余裕を広めに取る）。B は機種が分かってから。鉢に挿した札あり動画と、赤い物を植物の横・後ろ・床に置いた動画をお願いした（いまの動画は札を茎に付けてペットボトルに挿したもので、鉢の場面を確かめられない）。

- 「植物の近く」の判定は、いまの四角の判定で仕上げることになった（D64-a に追記）。切り抜きに接しているか・奥行きの差で見る案は残しておく

## 操作パネルと詳細の中身を広げる要件を決め、見本を作る

## 実行効率の見直し（読んで分かる範囲の分析と、安全な3点の修正）

プロジェクト全体を静的に読み、計算量・無駄な再計算・メモリ・キャッシュの余地を洗った。**計測はしていない（実機のプロファイルは未実施）**ので、効果は見積もり。DB は無い（D36）ので N+1 に当たる箇所は無い。

### 直したこと

- **仕込みの日記生成（`PlantStore.addToDay` / `seedFlipbook`）:** 日ごとに `diary` を頭から探して `Calendar.isDate` を呼んでいた（日数の二乗）。仕込みの間だけ「日（0時）→ 添字」の辞書を持たせて引くようにした。ページの足し方・主役の決め方は変えていない
- **`latestFlipbookRef`:** 先頭の1枚が要るだけなのに、全ページ分の写真リストを作っていた。新しいページから探して、見つかった時点で返す。並びは `flipbookPhotos(of:)` と同じ
- **`TalkStore.seededPhotos`:** ページごとの `isDate` をやめ、その日の範囲を1回求めて比べる
- **センサー中継サーバー（`store.ts`）:** 受信時に `measuredAt` を数値にして持つ。`recent` / `latest` が呼ばれるたび（アプリは1秒ごと）に最大 21,600 点の文字列を読み直していた
- **診断の要約（`summarize.ts`）:** 帯 × 指標ごとに `new Date()` していた時刻の取り出しを、点ごとに1回にした

確かめ方: `tsc --noEmit`、`npm run test:sensor`（17件）、`npm run test:metrics`（36件）が通る。iOS はシミュレータ向けのビルドが通る。

### 見送ったこと（と理由）

- **`photos(of:)` などの写真リストのキャッシュ:** 日記は数百ページ・写真は百枚ほどで、1回の組み立ては数十マイクロ秒の見込み。`@Observable` のプロパティには `didSet` を付けられず、無効化の入り口が `diary` の変更箇所すべてに散るため、古い一覧を出す不具合のほうが怖い。計測で重いと分かってからにする
- **植物検出の分類結果の並べ替え:** 並べ替えは約千件で、Vision 本体に比べて無視できる。表示するラベル（確信度が低いものも含む）が変わりうるので触らない
- **`recent` の秒数の上限:** 既存のテストが 7200 秒を使い、保管の上限（6時間）と同じ値にしかならず、何も減らないので入れなかった

### 直したこと

- **C1 電池と熱を数える（`EnergyMonitor`・新規）。**説明員用のパネルの「AR の診断」に5行を足した。計測を始めてからの電池の減り（5分を過ぎたら10分あたり）、熱の状態（今・最高・「熱い」以上だった時間）、植物の検出と札の検索の回数・平均処理時間・1分あたりの回数。「やり直す」で始め直す。`AppModel` に1つだけ持たせる（9/22 の、作り直しのたびに作られる件を避ける）

  - デモカメラの経路（`demoTick`）は Vision を使わないので触っていない
