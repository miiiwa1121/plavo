## カメラ画面に、センサー付きの植物の値を出す枠を付ける（D64）

> センサー付きの植物を判定して、詳細を画面上に表示するようにしたいです。モックセンサーがあり、それを検出して欲しいです。センサーがない時は、その枠の中に「検出できません。」と表示し、センサーを検知している時のみ、データが表示される感じです。

閉じた状態と開いた状態の画面イメージをもらい、そのとおりに作った。右端に白いつまみ（左の弧と同じ高さ）、押すと右から白い枠が出る（`SensorDrawer.swift`）。

- **「センサーを検知している」を、中継サーバーに繋がっていることでは判定できなかった。**サーバーは最後に受けた1点を返し続けるので、モックのガジェットを止めても 200 で同じ値が返る。計測時刻が進んだのを見た時刻を持ち、5秒進まなければ途切れたとみなす（`SensorClient.isLive`）
- 値を出すのは「植物が映っている」と「センサーが届いている」がそろったときだけにした。「センサー付きの植物を判定」なので両方が要ると判断した（D64）
- 原則2の例外になるので、決定事項に D64 として残した
- 確かめ方: シミュレータでデモカメラ（`-demoCamera`）と `-sensorBaseURL http://localhost:8787` で起動し、`npm run sensor` と `npm run mock:gadget` を動かす。ガジェットを動かす前は「検出できません。」、動かすと こすも が自動で選ばれて値が出る、止めると5秒で「検出できません。」に戻ることを見た。確認用に `-openSensorDrawer YES` を足した

次にやること: 実機で、実際のカメラの植物検出と組み合わせたときの見え方を確かめる。

### 枠の見た目を左の弧に揃え、つまみを上下に動かせるようにする

> 枠のUIは、左側面に配置してある植物切り替えバーと同じにして / 左の切り替えバー同じように、閉じている状態で右側面上でスライドできるようにして

- つまみを白い角丸から、**左の弧の通常円を左右に返した半円**に変えた。弧の図形（`ArcSegment`）をそのまま使う
- 半円と枠の地を、弧と同じガラスと白黒の色にした。弧の中に閉じていた明暗の規則（境目・色・縁の光沢の削り方・文字の色）を `EdgeChrome` に切り出し、弧とセンサーの枠の両方から使う。片方だけ直して左右で材料がずれるのを防ぐ
- 閉じた半円を上下に滑らせると置き場所が変わる。押して離せば開く。弧とは別の鍵（`sensorHandleOffset`）で覚える。枠が出てくる縦の範囲から出ない
- 詰まった点: 起動引数で `-sensorHandleOffset -150` と渡すと、`-150` が別の引数として読まれて効かなかった。確認は正の値で行った

### 形は指定のものに戻し、スライドで開け閉めする

> 形は私の指定の形にしてください。また、スライドで、開閉できるようにしてください。

「弧と同じにして」を形まで揃える意味に取って半円にしていたが、揃えるのは材料だけだった。**つまみと枠の形を最初の画面イメージ（縦長のつまみ・左の角だけ丸い枠）に戻し、材料（ガラス・白黒の地）だけ弧と同じにした。**

- **開け閉めを指に付けた。**枠を差し替えずに常に置き、右へ押し出す量を指の動きで変える。つまみは枠の左の縁に付いて動く。離したとき枠の幅の35%（勢い込み）を越えていれば開け閉めし、届かなければ戻る
- つまみの上の指は、最初に大きく動いた向きで分ける。上下なら置き場所の移動、左右なら開け閉め
- 詰まった点1: 枠を右へ払っても閉じなかった。**地は透明な色にガラスを掛けたもので、それ自体は指を受けない。**形ごと指を受けるようにした（`contentShape`）
- 詰まった点2: 閉じて画面の外にある枠の文字が、読み上げの対象に残っていた。隠れ切っているあいだは中身を描かないようにした
- 確かめ方: 指の操作はシミュレータに直接送れないので、使い捨ての UI テストで「左へ引く→開く、右へ払う→閉じる、少し引いて離す→閉じたまま、上下→動く、押す→開く」を流して通ることを見た（テストは消した）

### 開け閉めを、つまみの大きさの変化で見せる

> 開閉時のアニメーションは、突起部分のサイズの変動で表現して欲しいです。開くときは、突起部分が大きくなりながら開く。閉じるときは小さくなりながら下のサイズに戻る

- つまみと枠を別々に置いて枠を横から差し込む作りをやめ、**1つの図形を開き具合（0〜1）で変形させる**作りにした。大きさ・縦の位置（つまみの高さ→枠の高さ）・角の丸み（10→28）を同じ割合で動かし、右端は付けたまま。左の弧の「通常円と拡大円は同じ図形の変形」と同じ考え方
- 指で引いている途中も、引いた量がそのまま開き具合になる。離したあとはバネで開き切る／元のつまみに戻る
- 中身は開き切った大きさで組んで図形で切り抜く（途中の大きさで組むと行が折り返しながら伸び縮みする）。最初は途中のコマで「検出できません。」が枠の縁で欠けて見えたので、押して開くときは広がり切る直前に出し、閉じるときは縮み始める前に消すようにした
- 確かめ方: 使い捨ての UI テストで開け閉めを流しながらシミュレータを録画し、コマを切り出して見た（テストは消した）

### つまみを上下に動かすと震える不具合を直す

> 画面右側面を上下に移動させる動きに不具合がありそうです。上下に動かそうとすると、ブルブル震えます。

- 原因: 開け閉めを1つの図形の変形にしたとき、指を受ける口を**動く図形そのもの**に付けた。指の移動量をその図形を基準に測っていたので、つまみが動くと測った量が変わり、その量でまた動く、を繰り返していた。左右に引くときも、枠の左の縁が動くぶんだけ同じずれが起きる
- 直し方: 指の移動量を画面を基準に測る（`DragGesture(coordinateSpace: .global)`）
- 確かめ方: 使い捨ての UI テストでつまみをゆっくり下へ、続けて上へ動かしながら録画し、コマごとにつまみの縦の位置を測った。下へ動かす間は毎コマ下へ、上へ動かす間は毎コマ上へ進み、行き戻りは無かった（テストは消した）

## 紹介動画にセンサーの場面を足す（D64）

### 依頼

> カメラ画面に新しい機能を追加したので、そこを撮り直して欲しい。カメラ画面でリアルタイムのデータを確認できるもの。画面右側面に配置。センサーが付いている植物にのみ確認できる。動画上でもセンサーを指すと詳細情報が取れることを PR するシーンを作りたい。「日向に連れて行っても、うれしそう」の後に入れたい。

先に要件を詰めた。決まったこと: センサーを**土に差し込む動作**から見せる／センサーの絵は参考画像（`reference/sensor_mock`）から切り抜く／「検出できません。」は見せない／キャラクターは「今の気持ちがまるわかりだ！」／全体を1分40秒に／章は「話す」。

### やったこと

- **センサーの切り抜き**: 参考画像を macOS の Vision（前景のインスタンスマスク）に通したら、センサーだけがきれいに抜けた（`video/assets/sensor.png`）
- **刺す動き**（アプリの `DemoCamera`）: 台本の最後（名前をつけて17.2秒）にセンサーが上から降りてきて鉢に刺さる。鉢のふちから下は描かないので、土に刺さって見える。写真と同じ置き場所で組むので、手持ちの揺れにも一緒に付いてくる
- **値は本物の経路で届ける**: 値を出す枠（D64）はすでに実装されていた。値を送る側も `server` の中継サーバーとモックのガジェットがあったので、撮影ではそれを動かし、アプリは刺さった瞬間に取りに行く（ガジェットをまるに結ぶ）。**起動した直後には繋がない**——繋ぐと届いた水分（モックは15%から）で台本の「気持ち良い！」が上書きされ、株の自動選択も動く。モックのガジェットに `--percent` `--drying` `--lux` `--jitter` を足し、水をあげた直後（72%）・日向（18,000 lx）から、気温や湿度が少しずつ揺れるようにした
- `npm run record -- camera` が中継サーバーとモックのガジェットを立ち上げ、終わったら止める
- 台本（UIテスト）: 刺さったあと、右端のつまみを左へ引いて開き、5秒見せて右へ払って閉じる。つまみは「センサーの値」で見つけて、その位置から引く
- 動画: 「話す」に2場面（「センサーを刺すと、」→「今の状態を詳しく見られます。」＋キャラクター「今の気持ちがまるわかりだ！」）。刺さるところで鉢へ寄り、そのまま枠へ移る。刺さる音（insert）を足した。終盤の6画面のカメラも、センサーの枠を開いているところに替えた。語り手の文言はユーザーが決めていなかったので、提案した案を仮に入れた
- 撮り直しで、場面の時刻がすべて変わった（アプリの起動に時間がかかり、全体が約13秒後ろへずれた）。セリフの変わり目を測り直して台本を合わせた

### 詰まった点

- 横画面の吹き出しで「今の気持ちがまる／わかりだ！」と切れた。ワードジョイナーで「まるわかり」をつなぐと、文節の判定そのものが崩れて「今の／気持ちがまるわかり／だ！」になった。吹き出しの最大幅を広げて1行に収めた
- 短い一言（「どんな子かな」）で、吹き出しのしっぽが吹き出しから離れて浮いていた。しっぽの位置を左端から測っていたため。吹き出しを右端でそろえて置き、しっぽも右端から測るようにして、長さによらずキャラクターの頭を指すようにした
