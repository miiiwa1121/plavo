# 開発ログ 2026-08-31

実機でARの検出を検証し、見つかった問題を修正した日。

## 実機からの報告

初回の実機検証で3つの問題が報告された。

> 吹き出しはでます。少しぶれていたりしますが、空間にとどまることもある程度できていそうです。
> 逆に何もないのに吹き出しが出ていることが問題であると思います。
> また、検出時間などはなく、アプリを開いた瞬間に吹き出しが出ています。

**AR の基盤自体は動いていた。**ワールドトラッキングも投影も機能している。問題は検出の作りにあった。

## 見つけた問題と原因

### 1. 何もないのに吹き出しが出る — 設計の穴

`VNGenerateForegroundInstanceMaskRequest` は「**主要被写体**」の位置を返すだけで、**それが植物かどうかを一切見ていない。**机でも壁の角でも人でも、前景と背景が分離できれば何かを返す。

コードのコメントには「鉢植えのように画面の主役が1つだけある場面で最も安定する」と書いていたが、**「植物である」ことを確かめる処理を入れ忘れていた。**前景マスクの役割を取り違えていた——あれは位置を求める道具であって、種類を判定する道具ではない。

**修正**: `VNClassifyImageRequest` を挟み、2段構えにした。

```
1. 分類で「植物が写っているか」を判定する
2. 前景マスクで「どこにあるか」を求める
```

植物を表すラベル（`plant` `flower` `leaf` `foliage` `sunflower` など20語）の確度を合計し、しきい値を超えたときだけアンカーを打つ。あわせて、画面に占める面積が小さすぎる被写体も弾く。

### 2. アプリを開いた瞬間に吹き出しが出る

原因が2つ重なっていた。

- `lastDetectionAt` の初期値が0のため、**最初のフレームで検出が走る**
- 上の問題により、必ず何かが見つかる

加えて、**トラッキングが初期化中でもアンカーを打っていた。**この時点の位置は信用できず、吹き出しが飛ぶ原因にもなる。

**修正**: トラッキングが正常になるまで検出しないようにした。

### 3. 吹き出しがぶれる

毎フレーム素直に投影しており、ARKit の姿勢推定の微細な揺れがそのまま出ていた。

**修正**: 画面座標を平滑化した。

## しきい値を実機で調整できるようにした

植物の判定しきい値は、実物を見ないと妥当な値が決められない。診断パネルに**スライダー**と、**分類器が返したラベルの一覧**を出した。

```
植物らしさ   0.284 / しきい値 0.10
分類
  potted_plant        0.412
  flowerpot           0.198
  leaf                0.087
```

これで「何もないのに出る → 上げる」「植物で出ない → ラベルを見てキーワードを足す」という調整が現場でできる。

## 検証結果

> 何もないところで吹き出しが出ずに、植物の画像で吹き出しが出ることを確認できました。

**分類による判定が機能した。**AR の最大の未検証項目が1つ片付いた。

### まだ確認できていないこと

**今回は植物の「画像」で確認している。**平面なので、実物の立体的な鉢植えとは挙動が違う可能性がある。特に以下は実物でないと分からない。

| 項目 | なぜ画像では分からないか |
|---|---|
| 奥行きの妥当性 | 画面や紙は平面で、レイキャストの当たり方が実物と違う |
| 吹き出しの位置 | 植物の「少し上」が、立体だと見え方が変わる |
| 回り込み | 実物なら横から見られるが、画像ではできない |

**ただし副産物がある。**植物の画像で反応したということは、**印刷したパネルでも分類が効く**見込みが立った。セクション3のパネル方式にとって良い材料になる。

同時に、来場者がポスターや画面の植物に向けても反応する、ということでもある。展示では問題にならないが、性質として記録しておく。
