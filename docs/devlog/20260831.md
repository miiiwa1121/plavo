## 見つけた問題と原因

### 1. 何もないのに吹き出しが出る — 設計の穴

`VNGenerateForegroundInstanceMaskRequest` は「**主要被写体**」の位置を返すだけで、**それが植物かどうかを一切見ていない。**机でも壁の角でも人でも、前景と背景が分離できれば何かを返す。

コードのコメントには「鉢植えのように画面の主役が1つだけある場面で最も安定する」と書いていたが、**「植物である」ことを確かめる処理を入れ忘れていた。**前景マスクの役割を取り違えていた——あれは位置を求める道具であって、種類を判定する道具ではない。

**修正**: `VNClassifyImageRequest` を挟み、2段構えにした。

```
1. 分類で「植物が写っているか」を判定する
2. 前景マスクで「どこにあるか」を求める
```

植物を表すラベル（`plant` `flower` `leaf` `foliage` `sunflower` など20語）の確度を合計し、しきい値を超えたときだけアンカーを打つ。あわせて、画面に占める面積が小さすぎる被写体も弾く。

### 2. アプリを開いた瞬間に吹き出しが出る

原因が2つ重なっていた。

- `lastDetectionAt` の初期値が0のため、**最初のフレームで検出が走る**
- 上の問題により、必ず何かが見つかる

加えて、**トラッキングが初期化中でもアンカーを打っていた。**この時点の位置は信用できず、吹き出しが飛ぶ原因にもなる。

**修正**: トラッキングが正常になるまで検出しないようにした。

### 3. 吹き出しがぶれる

毎フレーム素直に投影しており、ARKit の姿勢推定の微細な揺れがそのまま出ていた。

**修正**: 画面座標を平滑化した。

## しきい値を実機で調整できるようにした

植物の判定しきい値は、実物を見ないと妥当な値が決められない。診断パネルに**スライダー**と、**分類器が返したラベルの一覧**を出した。

```
植物らしさ   0.284 / しきい値 0.10
分類
  potted_plant        0.412
  flowerpot           0.198
  leaf                0.087
```

これで「何もないのに出る → 上げる」「植物で出ない → ラベルを見てキーワードを足す」という調整が現場でできる。

### 7. カメラの画質と撮影

「画質が悪い」という指摘から始まったが、掘ると**目的は記録に残る写真の質**だった。

ARKit は既定でトラッキングを優先した控えめな映像形式を選ぶ。明示しないと端末の性能を使い切れない。

そして `captureHighResolutionFrame` を使えば、**ARを動かしたまま映像とは別に高解像度の静止画を撮れる。**カメラボタンを足し、撮った写真は今日の日記に入るようにした。

**映像形式の既定を「撮影優先」にした。**高解像度撮影に対応する形式はプレビューの解像度が下がることがあるが、**このプロダクトの価値は積み重なった記録にある**（D18-a）ため、記録の質を取る。

カメラアプリと完全に同等にはならない点は docs に明記した。解像度は本体カメラ相当まで上がるが、Deep Fusion などの計算写真処理は入らない。

**日記を植物で絞り込んだものにはしない。**日記は「その日に何があったか」、ギャラリーは「この子がどう育ったか」。目的が違う。日記は全体で一つだが、写真は撮った対象が決まっているので、そこから集める。

## 追記 — 弧の形を参考画像の比率に合わせた

「もう少し円を出してほしい」という指摘に対し、**感覚で動かさず、参考画像から比率を測って合わせた。**

| | 出っ張り | 縦半分 | 比 |
|---|---|---|---|
| 参考画像（iPhone のズーム） | 363px | 577px | **0.63** |
| 修正前 | 68pt | 161pt | 0.42 |
| 修正後 | 96pt | 152pt | **0.63** |

**形は「出っ張り ÷ 縦半分」の比で決まる**と分かったのが収穫。半径は弧全体の大きさを、中心の位置は深さを決める。この2つを分けて考えられるようになったので、次に「もっと浅く」と言われても迷わない。

それまでは半径と中心を一緒に動かしていて、大きさと深さが混ざっていた。**比を見つけたことで、調整が推測から計算になった。**

## 追記 — 素材に opacity を掛けて追従を殺していた

「バーの色が背景で変わらない」という指摘。原因は**濃さの調整に `.opacity()` を使ったこと**だった。

素材（`ultraThinMaterial`）は背後の映像を取り込んでぼかす仕組みだが、`.opacity()` を掛けると別レイヤーとして合成され、**背後の取り込みが切れる。**濃さを整えたつもりで、素材である意味を消していた。

**「薄くしたい」を opacity で解こうとしたのが短絡だった。**素材の濃さは種類（`ultraThin` / `thin` / `regular`）で選ぶか、上に薄い色を重ねて調整する。

指摘そのものは「選択中のタブの色を使っているのでは」という推測だったが、**観察（追従していない）が正しかった。**現象の報告は、原因の推測が違っていても価値がある。
