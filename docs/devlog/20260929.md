# 2026-09-29 開発ログ

## 紹介動画を Remotion で作る

### 依頼

> Remotionを使ってこのサービスの紹介動画を作りたいです。サービスの概要などではなく、実際の画面の操作感を伝える動画です。

縦型モニターに映すので縦長、尺は30秒程度、BGM はなし。

### やったこと

- **`video/` に Remotion のプロジェクトを作った。**1080×1920・30fps・約30.7秒。端末の枠に録画をはめ、上に章（マイプラント／日記／トーク／プロフィール）の切り替えと一言、最初と最後に「plavo／植物の気持ち翻訳アプリ」
- **操作は UIテストで台本にした**（`ios/PlavoApp/UITests/DemoTourTests.swift`・`project.yml` に `PlavoAppUITests` を足した）。ひまりを開く → 育成のグラフ → ギャラリー → 日記を友達・みんなへめくる → スタンプ 🌸 → ダブルタップで ❤️ → わが家のチャットで送る → プロフィールで2本指
- **`npm run record`**（`video/scripts/record.mjs`）でビルド・録画・台本・30fps への変換までを1回で流す
- **切り出しは `video/src/cuts.ts`** に、録画の秒で書いた。台本は操作のたびに待つので録画は約84秒あり、画面が止まっている間で切って詰めた
- アプリに**起動引数 `-showTouches YES`** を足した（`TouchIndicator.swift`）。指の位置に丸を出す

### 詰まった点

**指の跡が押した瞬間と合わなかった。**シミュレータの録画には指が映らないので、はじめは台本から押した時刻と位置を書き出し、Remotion の側で丸を重ねるつもりだった。ところが録画を見ると、操作が記録より早く映っていた。ずれは一定でなく、始めは約0.4秒、30秒あたりで約2秒。**simctl の録画の時刻が壁時計から少しずつずれている**（生の録画でも同じだったので、30fps への変換のせいではない）。時刻で合わせるのをやめ、**アプリ自身が指の位置に丸を描く**形に変えた。丸も画面と同じ録画に入るので、ずれようがない。

**プロフィールでピンチしたらトークへ移った。**画面全体に向けてピンチすると、片方の指がタブバーに乗り、寄せる動きでタブの選択を引っ張っていた（タブバーはなぞった指に付いてくる）。中央の写真1枚の上でつまむようにした。

**ピンチで列が増えすぎた。**XCUITest のピンチは勢いが付き、3列から10列近くまで進んだ。戻すピンチも狙った写真に当たらなかった。控えめにゆっくり1回だけつまむ形にした（3列 → 7列ほど）。

### 判断したこと

- **カメラ（AR）は入れていない。**ARKit はシミュレータで動かない。入れるなら実機の画面収録を切り出しの1つとして足す
- 文字は macOS の丸ゴシック（ヒラギノ丸ゴ）。描画は手元の Chrome で行うので、Web フォントを読み込まずに済む
- アクセントはアプリと同じシステムの緑。章の切り替えは、アプリの切り替えの部品（D55）に倣って塊が横へ移る

### 確かめたこと

- `npm run render` で `video/out/plavo-tour.mp4`（1080×1920・30fps・30.7秒）が書き出せる
- 書き出した動画をコマ送りで見て、つなぎ目に飛びがないこと、指の丸・スタンプ・❤️・キーボードの入力が映っていること

### 次にやること

- ユーザーに見てもらい、一言の文言・テンポ・場面の選び方を直す
- カメラ（AR）の場面を入れるかどうか。入れるなら実機で画面収録する
- 録画（`video/public/tour.mp4`・約15MB）をコミットするかどうか。`cuts.ts` はこの録画に合わせてあるので、コミットしないなら撮り直して合わせ直すことになる

## 紹介動画の60秒版を作る

### 依頼

> ・１分の動画を作成して欲しいです。・カメラ画面が大事です。・フォーカスしているところにズームするなどの動きが欲しい。・画面の説明寄りになりすぎたので、もう少し全体間のことも踏まえつつにしてみて・音源もつけてみて（音声はいらない）

30秒版のテロップの文言とテンポはよいと言われた。先に構成案を出して確認してもらってから作った。

### 決めたこと

- **話の流れで見せる。**上の表示をタブ名から「出会う → 話す → 残す → 分かち合う」に変えた。テロップの文体とテンポは30秒版のまま
- **カメラは実機も植物も無いので、アプリに撮影用の「デモカメラ」を足した**（案A。ダメなら実機でモニターに映した植物を撮る案Bにする約束）。写真を手持ちのように揺らして映し、見つけた判定だけを作り物にする。吹き出し・シャッター・迎える・名前の入力は本物
- 写真は Pexels のホヤの鉢植え（無料・商用可・クレジット不要）。アプリには同梱せず、起動引数で Mac 上のパスを渡す（シミュレータのアプリは Mac のファイルを読める）
- 動画に「※ カメラの映像はイメージです」と出す
- **BGM は OpenTracks（旧 DOVA-SYNDROME・9/15 に改称）の「Morning」（しゃろう）。**商用・動画・イベントで使えてクレジット不要。作曲者の追加条件なし。音源は単体での再配布が禁じられているので、リポジトリには入れない
- **効果音は自分で合成した**（外部の素材を使わない）
- 章の頭を BGM の小節の頭に合わせた。録音を測って約118 BPM、全体の演奏が入るのは約8.2秒
- 最初と最後はアプリのタイトルの絵（ユーザーが今日足した TitleScreen）をそのまま使い、キャッチコピーは「植物の気持ちが、聞こえたら。」
- 「残す」にひまりのパラパラ（一生を2秒で）を入れ、終盤に4つの画面を並べて引く場面を入れた（全体感）

### 詰まった点

- **吹き出しが画面の外へはみ出した。**写真の株が画面の幅いっぱいに近く、斜めに置く規則（D50）だと縁から出る。デモカメラのときだけ画面の内側に寄せた
- **水やりのあとが「ちょうどいい」止まりだった。**モックの水分は乾いたところ（15%）から始まり、待つ間に「……」（瀕死）まで落ちる。モックの1回ぶん（+45）では watered の帯に届かない。デモでは6秒後に72%まで上げる
- **録画が止まらず、次の撮影が始まらなかった。**台本が失敗したとき、録画のプロセスを止めずにスクリプトが終わっていた。失敗しても止めるようにした
- **BGM のダウンロードが401になった。**フォームの送信に `-X POST` を付けていたため、転送先にも POST で行っていた。外したら落ちた（プレビューの再生リンクは「ダウンロード不可」の指定付きなので使っていない）

### 見つけたこと（アプリの見た目）

**「はじめまして。名前をつけてくれる？」の吹き出しが、名前の入力欄に隠れる。**入力欄はキーボードの上160ptに固定で、株が画面の中ほどにあると吹き出しと重なる。実機でも起きうる。動画の都合でアプリの見た目は変えず、ユーザーに報告した。

### 確かめたこと

- 60秒版（1080×1920・30fps・60.05秒・音あり）を書き出し、コマ送りで流れとつなぎ目を見た。音量は平均 -16.4dB・最大 -2.4dB
- 3本の台本（`testDemoTour` / `testCameraTour` / `testFlipbookTour`）が通る。アプリのビルドが通る
- **確かめていないこと**: 音を耳で聞いての釣り合い（BGM と効果音の大きさ）。デモカメラ以外の経路（実機の AR）に影響がないことは、分岐の作りで確かめただけ（実機では動かしていない）

### 次にやること

- ユーザーに見て・聞いてもらい、寄り方・テンポ・音の大きさを直す
- 名前の入力欄と吹き出しが重なる件をどうするか
- パネルの廃止を docs に記録する（理由をユーザーに聞いている）
