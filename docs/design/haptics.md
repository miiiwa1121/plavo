# 触覚の設計（ハプティクス）

どこで何を鳴らすか、そして**どこで鳴らさないか**を決める。

最終更新: 2026-09-22
状態: **段階1（操作の触覚）と段階2（植物の触覚）を実装済み。**強さと長さの詰め（段階3）は実機待ち（D48）。

## 1. なぜ入れるのか

### 数を使わずに状態を伝える、3本目の経路

原則2で「計測値を数字のまま出さない」と決めた。いま持っている経路は**視覚**（葉の見た目・色）と**言葉**（セリフ）の2つだけで、どちらも画面の中にある。触覚は数を持たないまま「渇いている」を伝えられる、数少ない手段のひとつになる。

### 展示会場では音が使えない

会場は騒がしく、来場者はイヤホンをしていない。このアプリはいま音を鳴らさない作りだが、**触覚は騒がしくても届く。**音を足さずに手応えだけを足せる。

### 片手でARを覗いている姿勢では、画面の端で起きたことに気づけない

カメラ画面では、目は吹き出しと植物に向いている。撮れたのか、株が切り替わったのかは画面の端で起きるので、**見ていないと分からない。**手に返れば、目を動かさずに済む。

### 入れない理由

**「あると気持ちいいから」では入れない。**鳴らす場所を増やすほど、1つ1つの意味が薄れる。すべての操作が同じ手応えを返すと、手応えは「押した」以上の何も言わなくなる。

## 2. 2つの層に分ける

| 層 | 何を伝えるか | 材料 | 例 |
|---|---|---|---|
| **操作の触覚** | 機械がこちらの操作を受け取ったこと | 標準（`UIFeedbackGenerator` / `.sensoryFeedback`） | シャッター、弧の刻み、セグメント |
| **植物の触覚** | その子が居ること、どんな状態か | Core Haptics のカスタムパターン | 出会い、渇き、水を得た、看取り |

**層を混ぜない。**

操作の返事に植物のパターンを使うと、押した手応えが生き物の気配に化けて、何に対する返事なのか分からなくなる。逆に、**出会いに標準の success を使うと「登録という作業が完了した」音になる。**D9 で登録を出会いに溶かすと決めた以上、ここを作業の完了音にはできない。

**植物の触覚を鳴らすのは、植物が言葉を発する場面に限る。**触覚はセリフの伴奏であって、単独では鳴らない。

## 3. 原則

| # | 原則 | 理由 |
|---|---|---|
| H-1 | **変わった瞬間にだけ鳴らす** | 状態が続いている間は鳴らさない。帯域が変わっていないのに鳴ると、何が変わったのか分からなくなる |
| H-2 | **失敗していないものを、失敗として鳴らさない** | 「見当たらないなぁ」「まだ写真がありません」に `error` は鳴らさない（原則3 / D24）。見つからないのは来場者のせいではない |
| H-3 | **触覚だけで伝えない** | 必ず視覚か言葉が伴う。触覚が届かない端末・設定でも、体験は欠けない |
| H-4 | **一度に鳴るのは1つ** | 操作の触覚と植物の触覚が重なる場面は、時間をずらすか片方を落とす |
| H-5 | **取り返しのつかない操作を、軽く鳴らさない** | 削除とリセットに成功の三連を使わない（D18-a / D29） |
| H-6 | **連続では鳴らさない** | 鼓動を鳴らし続けない。電池を食い、数十秒で意味を失う |

## 4. 語彙

### 4.1 操作の触覚

| 名前 | 標準の対応 | 手触り | どこで |
|---|---|---|---|
| `tick` | `.selection` | 目盛りが1つ動いた | 弧の刻み、セグメント、写真の列 |
| `tap` | `.impact(.light)` | 受け取った | 開いた・閉じた・小さい確定 |
| `snap` | `.impact(.rigid)` | 決まった | シャッター、選択の確定 |
| `thud` | `.impact(.heavy)` | 重い | 削除・リセット |
| `caution` | `.warning` | 進めない | 上限、繋がらない |

**`error`（失敗の三連）は使わない。**H-2 のとおり、このアプリに「ユーザーの失敗」は無い。

**`success`（成功の三連）も使わない。**このアプリで嬉しいことが起きるのは植物の側なので、返すのは植物の触覚になる。

### 4.2 植物の触覚

Core Haptics でパターンを組む。強さと長さは実機で詰める（段階3）。

| 名前 | 手触り | 長さの目安 | いつ |
|---|---|---|---|
| `pulse` | 小さい2連（トクン） | 0.2s | 選ばれている株を検出した瞬間 |
| `meet` | 弱→強へふくらむ | 0.35s | **名前が決まった瞬間**（迎え入れの成立） |
| `thirst` | 硬く乾いた2連。弱い | 0.3s | `thirsty` / `critical` に入った |
| `drink` | 弱→強→ほどける連続 | 0.6s | `watered` に入った・水をあげた |
| `unease` | ざらついた弱い連続 | 0.5s | `overwatered` に入った |
| `farewell` | 長い減衰。1回だけ | 0.9s | 枯死に至った・株を削除した |

**`farewell` が鳴るのは、いまは株の削除だけ。**枯死は `Metrics.currentStage` が「最後の観察が `withered` なら `withered`」と定めていて、アプリは観察を記録するとき**いまの段階をそのまま書き戻す。**セッションの中で生きている株が枯れる経路が無い（仕込みのひまりは最初から一生分を持っている）。看取りの瞬間を作るなら、まず段階の進みかたを決めるところから。

**`comfortable` と `drying` には何も鳴らさない。**落ち着いている状態に手応えを付けると、落ち着いて見えなくなる。`drying`（20〜30%）はまだ「渇き」ではなく、そこで鳴らすと `thirsty` との差が消える。

**帯域の値を強さに連続で写さない。**帯域は6つしかなく、段で足りる。連続にすると、同じ帯域の中で手応えが揺れ続ける（モックは毎秒0.6%ずつ乾く）。

**「鳴らさない」も決めて書く。**書いていないところは、後から誰かが鳴らしてしまう。

## 6. 実装

### 6.1 置き場所

```
ios/PlavoApp/Sources/Support/Haptics.swift
```

`@MainActor` の単一の入口（`Haptics.shared`）にまとめる。**呼ぶ側に材料を選ばせない。**`Haptics.tick()` / `Haptics.plant(.drink)` とだけ書けるようにして、標準か Core Haptics かは中で決める。

鳴らす場所が散らばると、§5 の表と実物が合っているかを確かめられなくなる。

### 6.2 標準の語彙

SwiftUI の `.sensoryFeedback(_:trigger:)`（iOS 17+。本アプリの最低は iOS 18）と `UIFeedbackGenerator` を使い分ける。

| 使い分け | 使うもの | 例 |
|---|---|---|
| 状態の変化がそのまま契機になる | `.sensoryFeedback(_:trigger:)` | シャッターの種類、セグメント、列の1枚 |
| 非同期の完了・条件付きの発火 | `Haptics` から直接 | 撮影の完了、上限、帯域の変化 |

**生成器は使う直前に `prepare()` する。**呼んでから鳴るまでの遅れが縮む。シャッターのように「押す前から鳴ることが決まっている」場面では効く。

### 6.3 植物の触覚（Core Haptics）

| 項目 | 方針 |
|---|---|
| 対応の確認 | `CHHapticEngine.capabilitiesForHardware().supportsHaptics`。使えない端末では**標準の語彙に落とす**（`meet`→`snap` など）。無音にはしない |
| 音を鳴らさない | `engine.playsHapticsOnly = true`。ARKit のカメラセッションと音声の取り合いを避ける |
| エンジンの生存 | `stoppedHandler` / `resetHandler` で開始し直す。バックグラウンドから戻ると止まっている |
| 開始のタイミング | 初回の再生時に起こす。起動時には作らない——一度も鳴らさない画面でも持ち続けることになる |
| 先に起こす | **カメラを開いたときだけ温めておく**（`Haptics.prepare()`）。植物の触覚が鳴るのはほぼこの画面で、最初の1つは「見つけた瞬間」（`pulse`）になる。寝たまま迎えると、いちばん効かせたい1発が遅れる |
| 寝かせる | `isAutoShutdownEnabled = true`。止まったことは `stoppedHandler` で覚えておき、次に鳴らすときに起こし直す |
| パターンの持ち方 | **コードで組む。**`.ahap` ファイルにすると、帯域の定義（`moisture.json`）と手触りが別の場所に離れる。値を並べて読めるほうがよい |
| 失敗したら | 黙って何もしない。触覚が出ないことでアプリを止めない（H-3） |

### 6.4 直したところ

弧は、名前が頂点を通るたびに `UISelectionFeedbackGenerator` を**新しく作っていた。**

```swift
UISelectionFeedbackGenerator().selectionChanged()   // 直す前
```

- 生成器はハードウェアを温めてから鳴らすもので、作ってすぐ鳴らすと最初の1回が遅れる
- `prepare()` を呼んでいないので、回し始めの手応えが鈍い

**回し始めに1つ作って持ち、離したら手放す形にした。**`Haptics.Ticker` を `beginTurning` で作り、`onEnded` で手放す。刻むたびに次の `prepare()` を掛けておく。

## 7. 鳴らない条件

触覚は「鳴らないことがある」前提で組む。**鳴らなくても体験が欠けない**ことは H-3 で担保してあるが、展示当日に鳴らないのは避けたい。

| 条件 | どうなるか | 対処 |
|---|---|---|
| シミュレータ | 鳴らない | **実機でしか確かめられない。**カメラタブと同じ制約 |
| 低電力モード | 鳴らなくなる | 展示の端末は電源に繋ぐ。当日の確認項目に入れる |
| 設定 > サウンドと触覚 の触覚がオフ | 鳴らない | 展示端末はオンで固定する |
| Core Haptics 非対応の端末 | 植物の触覚が出ない | 標準の語彙に落とす（§6.3） |
| バックグラウンドから復帰 | エンジンが止まっている | ハンドラで起こし直す |

### 実機で確かめること

- [ ] ARのカメラセッションが動いている間、触覚が鳴るか・遅れないか
- [ ] `captureHighResolutionFrame` の最中と直後に鳴らして、撮影が乱れないか
- [ ] 低電力モードで実際にどうなるか
- [ ] 弧を速く回したとき、`tick` が詰まらずに刻めるか
- [ ] 片手で持ち、立った姿勢で、`thirst` と `drink` を取り違えないか

## 8. 進め方

| 段階 | 中身 | 状態 |
|---|---|---|
| **1** | `Haptics.swift` と**標準の語彙だけ**。§5 の表のうち「操作」の層すべて。弧の生成器の直し（§6.4）を含む | **実装済み**（シミュレータでビルド確認。**触覚そのものは実機でしか確かめられない**） |
| **2** | Core Haptics のエンジンと植物の語彙。カメラの検出・帯域・名前の確定に繋ぐ | **実装済み**（同上。**手触りは実機でしか分からない**） |
| **3** | **実機で強さと長さを詰める。**展示の姿勢（片手・立って・騒がしい）で確かめる | **次はここ。**§4.2 の数値は出発点にすぎない |
| **4** | （任意）切る手段 | 未着手 |

**段階1と2を分ける。**段階1は鳴る場所が既存の操作に閉じていて、外したければ消せる。段階2は手触りそのものを作る仕事で、実機がないと何も決まらない。
