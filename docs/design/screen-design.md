# 画面設計

各画面の要素・状態・遷移を定義する。**実装しながら迷わないことを目的とする。**

最終更新: 2026-08-30

## 1. 全体の構造

タブ構成（D13）。起動時の既定はカメラ（D2）。

```
TabView
├── カメラ        AR。向けた対象で振る舞いが変わる。このアプリの主役
├── マイプラント   育てている植物の一覧と詳細
├── 日記          記録を読む・書く
├── ルーム        準備中（D21により実装対象外）
└── マイページ    自分の歩み・設定・展示運用
```

**展示のフロー（説明 → AR → 時系列 → センサー）はアプリの構造とは無関係。**説明員と物理配置が担う。

## 2. 共通のルール

### 2.1 数値を見せない（原則2）

どの画面でも、計測値や導出指標を数字のまま出さない。植物の言葉か、視覚的な表現に翻訳する。

| 出さない | 代わりに |
|---|---|
| 土の湿り 18% | 葉がしおれた見た目、「のどが渇いたよ」 |
| 開花予測 10月12日 | 「あと12日で咲くよ」 |
| 積算光量 4.2 mol/m²/day | 「今日はあまり光を浴びてないよ」 |

**例外は説明員用の隠し表示のみ。**長押しで開く場所に限る。

### 2.2 空状態をエラーにしない（原則3）

まだ何もない状態を「失敗」として見せない。植物の側の言葉で書く。

| 状況 | 書かない | 書く |
|---|---|---|
| 植物が未登録 | 「植物が登録されていません」 | 「まだ誰にも会っていません」 |
| 記録がない | 「データがありません」 | 「これから増えていきます」 |
| 見つからない | 「検出に失敗しました」 | 「見当たらないなぁ」 |

### 2.3 データの寿命（D36）

展示では永続化しない。

| 種類 | 出どころ | 寿命 |
|---|---|---|
| 仕込みの記録 | アプリ同梱の `timeline.json` | 常にある。書き換わらない |
| セッション中の追加 | 来場者の操作 | **リセットで消える**（D33） |
| セリフのプール | アプリ同梱の `dialogues/` | 常にある |

製品版では SwiftData + CloudKit に載せる（D19）。

### 2.4 向き

縦持ち固定。上下反転のみ許可（D38）。

## 3. カメラ

**このアプリの主役。**向けた対象によって振る舞いが変わる。

### 3.1 状態

```
起動
 └→ [未検出] ──植物を検出──→ [はじめまして] ──名前を入力──→ [観察中]
       │                          （未登録のときだけ）
       │
       ├──植物を検出（登録済み）──→ [観察中]
       │
       └──パネルを検出──→ [再生中]
```

| 状態 | 画面 |
|---|---|
| 未検出 | カメラ映像のみ。下部に「見当たらないなぁ」（D24） |
| **未登録・未選択** | **同上。株が決まっていないあいだは植物を探さない**（D40-a） |
| はじめまして | 吹き出しに「はじめまして。名前をつけてくれる？」＋名前の入力 |
| 迎える（確認） | 撮った1枚で画面が止まる。植物に枠。「撮り直す」「話しかける」（D40） |
| 観察中 | 吹き出しにセリフ。センサーの状態に応じて変わる |
| 再生中 | 吹き出しにその日の記録。上部にキャプション（「45日目・開花」） |

### 3.2 登録フロー（D9 / D40-a）

**専用の登録画面を作らない。**登録という作業を出会いという体験に溶かす。

1. シャッターの「迎える」で撮り、相手を確かめる（§3.2-b）
2. 吹き出しに「はじめまして。名前をつけてくれる？」が出る
3. 吹き出しの下に名前の入力欄が現れる
4. 名前を入れると登録が完了し、通常の観察に移る

**入力するのは名前ひとつだけ。**種類はAIが推定し、後からマイプラントで直せる。

**入口はここだけ（D40-a）。**カメラを向けただけでは始まらない。**株が未登録、またはどれも選ばれていないあいだは植物を探さず**、「見当たらないなぁ」を出す。

| 状態 | カメラを向けると |
|---|---|
| 株が選ばれている | その子として観察する |
| 未登録・未選択 | **見当たらないなぁ**（探さない） |
| パネル（D33） | **選択の有無に関わらず再生する。**画像アンカーのため別経路 |

**名前をつけている間はセリフを引き直さない。**土は乾かし続けるが、言うことは出会いのまま止める。引き直すと「はじめまして」が最初の刻みで水分のセリフに置き換わる。

展示では、来場者ごとにリセットされると未登録に戻る。**毎回「迎える」から始まる**のは展示として正しい。

### 3.2-b 植物を迎える（D40 / D40-a）

**株を迎える唯一の入口（D40-a）。**1株目も2株目以降も、ここを通る。

| # | 操作 | 画面 |
|---|---|---|
| 1 | シャッターを**左右にスライド**して「迎える」を選ぶ | 選択中が中央に大きく、残りは横に小さく並ぶ。下端のどこを滑らせても切り替わる |
| 2 | シャッターを押す | 高解像度で1枚撮る |
| 3 | — | **その1枚で画面が止まり、見つけた植物に枠が出る。**下に「この子でいい？」 |
| 4 | 「話しかける」を押す | 通常のカメラ画面に戻る。シャッターは「撮る」に戻る |
| 5 | — | 確かめたその子が「**はじめまして。名前をつけてくれる？**」＋名前の入力 |

3で「撮り直す」を選べば2に戻る。

**「迎える」に切り替えているあいだ、弧は退く（D40-b）。**半径を 40 → 22 に落とし、名前を出さず、触れなくする。これから新しい株を迎えようとしているのに、いま選ばれている株の名前が出ていると相手を取り違える。開いて選べてしまうと、選んだのに名前が出ない状態になるため、触れる先も閉じる。

**名前を入れているあいだは、下の要素を持ち上げない。**キーボードが出ても動くのは入力欄だけ。

| 要素 | キーボードが出たとき |
|---|---|
| 吹き出し | **動かない。**位置はARの投影で決まるので、ずれると植物から離れる |
| シャッター | **出さない。**撮る場面ではない |
| 弧・下部の案内 | 動かない |
| タブバー | **退ける。**留めてもキーボードの下に隠れる位置にあり、見え方は変わらない |
| 名前の入力欄 | キーボードの上まで上がる |

タブバーは `TabView` のもので、カメラ画面側の `.ignoresSafeArea(.keyboard)` では止められない。`.toolbar(.hidden, for: .tabBar)` で退ける。

**確認中の操作はタブバーに重ねない。**写真だけを安全領域の外まで広げ、「撮り直す」「話しかける」は内側に置く。

**シャッターの記号は大きさを固定する（18pt）。**ボタンの大きさに比例させると、切り替えのたびに字が組み直されて揺れる。記号は塗らずに**くり抜く**——黒で描くと白丸に点が乗って見えるが、抜けば向けている先が透ける。

**確認中は検出を止める。**止めないと、確かめている裏で映像の側が別の相手を決めてしまう。

**確かめた相手をそのまま引き継ぐ。**戻ってから検出し直さない。検出し直すと見つかるまで間が空き、押した手応えが消える。

**枠が出なくても進める。**見つけられなかったときは「うまく見つけられなかったみたい」と出すが、「話しかける」は押せる（D24・原則3）。

### 3.2-d 直近の1枚（D42）

撮った1枚を**左下**に出す。位置と役割はカメラアプリに倣う。

| 操作 | 何が起きるか |
|---|---|
| 撮る | 左下の1枚が入れ替わる |
| タップ | **その画面のまま**大きくなる |
| どこかを触る | 戻る |

**シャッターと同じ高さに置く。**撮る手と見る目が同じ帯に収まる。

**「迎える」で撮った1枚は出ない。**あれは相手を確かめるためだけのもので、日記には入らない（D40）。

**画面を移らない。**別の画面へ送ると、見終わったあとにカメラへ戻る手間が要る。

**未撮影でも枠は置く。**まだ1枚も撮っていないうちから、同じ場所に同じ大きさの空の枠を出す。

| 状態 | 見えるもの | 触れるか |
|---|---|---|
| まだ1枚も無い | 空の枠（暗い地＋白い線） | **触れない** |
| 1枚以上ある | 直近の1枚 | タップで拡大 |

**行き先を、撮る前から見せる。**何も無いところに1枚目が現れる作りだと、撮ったものがどこへ行ったのかを**その瞬間に見ていないと分からない。**先に空の枠が見えていれば、撮ったあとはそこが埋まるだけになる。

空の枠には**暗い地を敷く。**線だけだと映像が枠の中を素通りして、空いている場所ではなく映像に乗った線に見える。

**空のあいだは触れる先にしない。**開く1枚がまだ無いうえ、下端はシャッターを滑らせて切り替える帯でもある（D40）。

### 3.3 セリフの出し分け

| 契機 | 出すもの | 出どころ |
|---|---|---|
| 検出した瞬間 | 短い一言（「はにゃ？」） | `greeting.json`・通信不要 |
| その1.2秒後 | 状態に応じたセリフ | `moisture.json` ほか |
| 帯域が変わったとき | 新しいセリフに差し替え | 同上 |
| パネルを検出 | その日の記録 | `timeline.json` |

**同じ帯域では引き直さない。**毎秒変わると読めない。

### 3.2-a 観察中の株を選ぶ（D39 / D41）

画面の左端に弧状のUIを置く。iPhone のカメラでズームを長押ししたときの円弧に倣う。以下ではこれを**サイドバー**と呼ぶ。

**部品の呼び方を決めてある（D41-b）。**タブバーを手本にしているので、**対応する部品には対応する名前**を付ける。話すときと書くときで名前が違うと、どこを直しているのかが通じない。

| 呼び方 | タブバー（手本） | サイドバー |
|---|---|---|
| **全体枠** | バーそのもの | **通常円**（触っていないときの小さな半円）／**拡大円**（触っているときの大きな弧） |
| **囲い枠** | 選択中を囲う塊 | 頂点の名前を囲う塊 |
| **文字** | 項目名＋アイコン | 名前 |

| 指の動き | 何が起きるか |
|---|---|
| 通常 | **左端に無地の小さな半円。名前は出さない**（名前は上部のアイコンの下） |
| **「迎える」中** | **さらに小さくなり、触れない**（D40-b） |
| **押さえたまま待つ**（0.175秒） | 弧が開き、いま決まっているものが指定の場所に来る |
| **そのまま上下に滑らせる** | **名前の列が回る。**指定の場所を通るたびに色が変わり、触覚が鳴る |
| **指を離す** | **その時点で指定の場所にあるものが決まる** |
| **すぐ上下に動かす** | バーの置き場所を変える。持ち方に合わせられる |
| 離して0.4秒 | 自動で閉じる |

**選び方はダイヤル（D41）。**指定の場所＝弧の頂点（縦中央）は動かず、名前のほうが回ってくる。

| | 動くもの | 決まる契機 |
|---|---|---|
| 変更前 | 指 | 通過した瞬間 |
| **D41** | **名前** | **指を離したとき** |

- 名前1つあたり 16°、指の移動 44pt で1つ進む
- 端で止まる。ぐるりとは回らない
- 頂点から離れるほど薄くなり、48° で消える。**止まっているとき、ちょうど5つ見える**
- 通過は**仮選択**。色と触覚で知らせるが、まだ決まっていない

**消える角度は「6つ目がちょうど消える位置」に置く**（16° × 3）。中途半端に残ると、画面の縁で切れた文字が見える。

**名前は円の中心に向けて寝かせる。**中心は画面の外（左）にあるので、頂点では水平、上下に離れるほど傾く扇になる。**決まっているものは常に水平**なので、いちばん読みやすい。

**一覧の先頭は「未設定」。**選ぶと誰も見ていない状態に戻り、カメラは見当たらない扱いになる（D40-a）。**観察をやめる操作**として機能する。

**閉じているあいだ、弧は名前を出さない。**決まっている株の名前は画面の上（アイコンの下）に出るので、ここに出すと二重になる。弧は触るまで無地の半円でいる。

**選択の印は、下のタブバーと同じ動きにする（D41-a）。**

| 状態 | 印 |
|---|---|
| 止まっている | 頂点の名前を包む長円 |
| 回している | **縦に伸び、出ていく名前と入ってくる名前をまたぐ** |
| 名前の色 | **塊の縁を境に切り替わる。**半分かかっていれば半分だけ変わる（フェードではない） |

タブバーは印のほうが移動するが、弧では**印が止まっていて名前が動く**。動くものが逆なので、「A から B へ旅する」動きは「頂点で伸び縮みする」に置き換える。

**囲い枠はべた塗りにする（D41-b）。**タブバーで Liquid Glass なのは**全体枠（バー本体）のほう**で、選択中を示しているのは無彩色の塗りひとつ。**以前はここが逆で、囲い枠にガラスを付けていた。**囲い枠はすでにガラス（全体枠）の上に乗っているので、重ねてもぼかす先が無い。

囲い枠は着色しない——色が付くのは中身の名前だけ。**塊はいつも地より明るい**（暗い地には薄く白を重ね、明るい地では白で塗り切る）。

**名前は弧からはみ出さない。**収まらなければ「こもれび…」と切る。

**名前は半径に沿って寝ているので、はみ出すかどうかは半径で決まる。**使える範囲は外側が弧の縁、内側が画面の左端。円の中心が画面の外にあるぶん、**角度が開くほど内側の限界が遠のいて範囲が狭くなる**ので、端の名前ほど短く切られる。

| 角度 | 使える幅 |
|---|---|
| 0°（頂点） | 84 |
| 16° | 81 |
| 32° | 71 |
| 48° | 60 |

**名前の囲い（印）も、止まっているあいだは縁からはみ出さない。**回している最中は伸びるので、はみ出してよい。

**頂点のアイコンは、円の中心の側から出入りする。**外へ湧いて出るのではなく、弧の内側から現れ、そちらへ引っ込む。

**頂点に来ている株のアイコンを、円の外側の決まった場所に出す。**

| 頂点にあるもの | 円の外側 |
|---|---|
| 株 | **その株のアイコン** |
| 未設定 | 何も出ない（アイコンが無いため） |

**位置は固定する。**名前に添えると**その長さで位置が動き**、「ここが頂点だ」という印としての意味が薄れる。場所が動かないからこそ、**名前のほうが回っている**ことが分かる。

弧の縁から 32pt 外に置く。塗りから出るので映像の上に独立して立つ（縁取りと影を付ける）。名前がここまで届くことはない。

**触れた瞬間には開かない。**即座に開くと長押しの感じがなく、意図せず開いてしまう。

**閉じるのは速くする。**開いたまま長く残ると映像の邪魔になる。ただし**離してから決まる方式にしたぶん、少し長く残す**（0.2 → 0.4秒）。即座に畳むと、何が選ばれたのかを見る間がない。

### 3.2-c 上中央のアイコン（D41）

**いまどの株を見ているかを、画面の上に常に出す。**弧は触らないと何も語らないので、それまでは見ている相手が分かるのが触れた一瞬だけだった。

| 状態 | 上中央 |
|---|---|
| 株が選ばれている | その株のアイコン（写真、無ければ生育段階の記号）と、**その下に名前** |
| **未設定** | **何も出さない。**誰も見ていないことは、何も無いことで伝わる |
| 「迎える」中 | 出さない。弧と一緒に引っ込む |
| パネル再生中 | **アイコンが上、キャプションが下**に縦に並ぶ |

**名前の置き場所はここひとつ。**弧は閉じているあいだ無地の半円でいるので、二重にならない。

**回している最中も、ここは変わらない。**上は決まっているものを、弧は考えている途中のものを示す。離して決まった時点で、上の名前も入れ替わる。

**円を丸ごと描き、画面の縁で切る。**帯（ドーナツ）にすると縁から浮いてしまい、貼り付いて見えない。

**開くと円の中心が画面の外へ出る。**iPhone のカメラのズームと同じ作りで、半円を端に貼るより弧が緩やかになり、目盛りらしく見える。閉じているときは中心が縁の上にあるので、そのまま半円として見える。

**形は「出っ張り ÷ 縦半分」の比で決まる。**参考にした iPhone のズームはこの比が約 0.63。中心を縁に寄せるほど深い弧に、遠ざけるほど浅くなる。**半径は弧全体の大きさを、中心の位置は深さを決める**——この2つを分けて考えると調整しやすい。

現在は半径 169 / 中心 -73（出っ張り 96pt・縦半分 152pt・比 0.63）。

**閉じた半円と開いた弧は、同じ図形の変形として扱う。**別のビューに差し替えると「消えて出てくる」動きになり、広がったように見えない。半径と中心の位置を補間すると、半円がそのまま弧へ育つ。名前も半円の中から扇のように散る。

**選択は枠ではなく色で示す。**選択中はタブバーと同じ色。**アプリの中で「いま選ばれているもの」の示し方を1つに揃える**ため。枠があると弧の上でうるさく、映像も余計に隠れる。

**全体枠（通常円・拡大円）はタブバー本体と同じ Liquid Glass にする（D41-b）。**タブバーと並んで映るものなので、材料が違うと同じアプリの部品に見えない。

**縁の光沢は弱める。消しはしない。**タブバーの全体枠にも同じ光沢があるので、無くすと材料が違って見える。ただし**弧は輪郭の片側しか見えないぶん、同じ光沢でも一本の白線として強く出る**——タブバーでは枠を一周するので、線ではなく丸みとして馴染む。

**削る幅だけ大きく描き、元の大きさで切る。**いちばん明るいところが切り取られた外側に落ち、内側の淡いところだけ残る。大きくするのはガラスだけで、弧の大きさ（＝頂点の位置）は変えない。

| 地 | 削る幅 |
|---|---|
| 暗い | 1.5pt。**白い光沢は黒地でいちばん際立つ** |
| 明るい | 0.5pt。地に紛れるので、ほとんど削らない |

**ただし色を掛けて使う。ぼかしだけでは足りない。**SwiftUI の `Material` も UIKit の `UIVisualEffectView` も、**ARKit が Metal で描くカメラ映像を取り込めない。**素材を置いても地の色が出るだけで、背景が変わっても色が動かなかった。Liquid Glass が取り込めるかは実機で確かめる必要があるが、**取り込めていなくても明暗が付いてくるように**、実測した明るさから作った色を掛けておく。

明るさは **ARKit が毎フレーム渡してくる推定値**（`ARLightEstimate.ambientIntensity`）を使う。

| 項目 | 値 |
|---|---|
| 明るさの範囲 | 0〜2000ルーメンを 0〜1 に写す |
| 追従の速さ | 毎フレーム 8% ずつ寄せる。照明のちらつきで色が揺れないように |
| 濃さ | 0.82 で固定 |

**地は白か黒のどちらか。途中の灰色は作らない（D41-b）。**タブバーは周りの明るさで白い地と黒い地を切り替えるだけで、あいだを取らない。**サイドバーだけが連続で変わると、並んだときに別の作りに見える。**

| 状態 | 地 | 名前（選択外） | 囲い枠 |
|---|---|---|---|
| 暗い | 白 0.06 | 白 0.72 | 白 0.20 |
| 明るい | 白 0.92 | **黒 0.66** | 白 0.92 |

**切り替わる明るさは、入るときと出るときでずらす**（0.58 で明るいへ、0.42 で暗いへ）。境目がひとつだと、そこで明るさが揺れるたびに白黒が往復する。切り替わりは目に付くので、色だけを 0.28 秒かけて移す。

診断に実測値を出してある。追従しているかを数字で確かめられる。

**選択が変わるたびに触覚を返す。**ダイヤルを回したときの手触りに揃える（`UISelectionFeedbackGenerator`）。

**移動と選択は指の動きで振り分ける。**先に動かせば移動、押さえたままなら選択。iOS のホーム画面と同じ流儀で、迷いなく使い分けられる。置き場所は覚えておき、次に開いたときも同じ位置に出る。

**塗りつぶしの半円にはしない。**カメラ映像を覆いすぎるため、名前が乗る帯だけを敷く。

**株が少ないときは弧の広がりを狭める。**上限いっぱいに広げると、名前が弧の両端に張り付いて不格好になる。

**触れる範囲は開閉をまたいで1つに保つ。**開いた瞬間にビューが入れ替わると、その上のジェスチャが切れ、「押したまま滑らせて選ぶ」が途切れる。

**`onTapGesture` と `onLongPressGesture` を併用しない。**タップ側が先に触れを掴み、長押しが成立しない。触れた時点で開き、そのまま滑らせれば選べる形にする。

### ガジェットによる自動選択

センサーの `gadgetId` と株が紐づいていれば、値が届いた時点でその株に切り替わる。

**自動で切り替わったときも一度開く。**黙って変わるとユーザーが気づけない。開いて、選択されたことを見せてから、触られなければ閉じる。

紐づいていないガジェットから値が来た場合、**生きている株が1つだけのときに限って自動で結ぶ。**展示は1株1ガジェットなので手間なく繋がる。複数あるときは勝手に決めない——間違えると記録が混ざる。

### 3.3-a 撮影

画面下中央にシャッターがある。**撮った写真は今日の日記に入る**（D26 / 1日5枚まで）。

**映像フレームの保存ではない。**ARKit に高解像度の1枚を改めて撮らせている（`captureHighResolutionFrame`）。**記録に残る写真の質は、画面で見える映像の質とは別に決まる。**

| 状況 | 表示 |
|---|---|
| 成功 | 「日記に追加しました（2/5）」 |
| 上限 | 「今日はもう5枚あります」 |
| 未登録 | 「先に植物を登録してください」 |

**カメラアプリと完全に同等にはならない。**解像度は本体カメラ相当まで上がるが、Deep Fusion や Smart HDR といった計算写真処理は入らない。ARKit の制約。

### 3.4 説明員用（長押し1.5秒）

来場者には数値を見せないため隠す。

- ARの診断（トラッキング状態・特徴点・検出の成否・分類ラベル・しきい値）
- モック操作（水をあげる・水分スライダー）
- 再検出・リセット

### 3.5 AR非対応の環境

シミュレータでは ARKit が動かない。「ARはこの環境では動きません」と表示し、実機を促す。

## 4. マイプラント

育てている植物の一覧と詳細。**数値のダッシュボードにしない**（原則2）。

### 4.1 一覧

| 要素 | 内容 |
|---|---|
| アイコン | **写真を設定できる。**未設定なら生育段階に応じた記号を出す |
| 植物のカード | 名前・種類・一緒にいる日数・いまの様子 |
| 「いまの様子」 | 帯域のラベル（「水不足」ではなく「のどが渇いている」寄りの表現） |
| 空状態 | 「まだ誰にも会っていません。カメラを向けてみてください」 |

**展示では1株を想定するが、複数株に耐える作りにする。**保持数は少数精鋭（L-5）。

### 4.2 詳細

タップで開く。

| 節 | 内容 |
|---|---|
| **アイコン** | 画面上部に大きく1つ。**右下の「+」から写真を選ぶ** |
| 見出し | 名前・種類・一緒にいる日数・出会った日 |
| いまの様子 | 最後に言ったこと（セリフ）。数値は出さない |
| これまでの歩み | 生育段階の推移を時系列で。到達した段階に印をつける |
| 記録 | 観察の履歴。日付とそのとき言ったこと |

**種類の修正**をここでできる（D9）。AIの推定が外れたときのため。

**写真は切り抜く範囲を選べる。**そのまま丸く切ると狙った場所が入らないため、拡大と移動で位置を合わせてから確定する。**元画像から直接切り抜く**——画面を描画してから縮小すると解像度が落ちる。

写真を外す操作は下部にまとめる。**上部はアイコンと「+」だけに保つ。**

**看取った株は、その日で日数の数えを止める。**死後も「一緒にいる日数」が増え続けるのは、植物を人と同等に扱うという軸（D18-a）と合わない。

### 4.4 ギャラリー

詳細は**情報とギャラリーの2画面**で、上部のセグメントとスワイプで行き来する。

**ギャラリーにはその株の写真だけが集まる。**日記が「その日に何があったか」なのに対し、ギャラリーは「この子がどう育ったか」。目的が違うので、**日記を植物で絞り込んだものにはしない。**

| 要素 | 内容 |
|---|---|
| 並び | 3列の正方形グリッド。新しい順 |
| 出どころ | その株に紐づく日記の写真 |
| タップ | 大きく表示。左右にスライドして前後へ |
| 空状態 | 「まだ写真がありません。カメラから撮ると、ここに集まります」 |

写真は日記と同じく、**先に正方形を確定させてから流し込んで切り抜く。**縦長・横長でグリッドが崩れないようにするため。

### 4.3 削除（D29）

削除できる。ただし**強い確認を挟む。**

> この子との記録がすべて消えます。
> 一緒に過ごした34日分の日記も戻せません。

確認の文面で**何が失われるかを明示する。**D18-aで「植物を人と同等に扱う」と決めた以上、一覧からスワイプで静かに消えるのは矛盾する。

## 5. 日記

**基本はユーザーが書き、自動生成モードも持つ**（D14）。絵は観察時の写真（D26）。

### 5.0 日記の単位 — 1日1ページ、全体で一つ

**日記は投稿ではなく日誌。**日が変われば**自動でページが増える。**ユーザーが「作る」操作をしなくてよい。

**書かなかった日も「お休み」としてページが残る。**D18-a で時間の積み重ねを価値の中心に置いた以上、記録しなかった日を無かったことにはしない。サボった日も一緒に過ごした日である。

**日記は植物ごとではなく全体で一つ。**複数の株を育てていても、その日のページは1枚。

株ごとに記録を辿る手段は、マイプラントのギャラリーが担う（§4.4）。**日記の複製ではない。**

| 規則 | 内容 |
|---|---|
| 1日1ページ | 同じ日に2ページは作らない |
| 自動追加 | 起動時と前面復帰時に、今日のページが無ければ作る |
| 写真 | 1日あたり最大5枚（`DiaryEntry.maxPhotosPerDay`） |
| お休み | 本文が空で写真も無い日 |

### 5.1 一覧 — 3列グリッド

**日付の新しい順に、3列の正方形グリッドで並べる。**

縦積みのカードでは1画面に2件しか入らず、**記録が積み上がっていることが伝わらない。**グリッドなら3ヶ月分が一目で見渡せる。

| 要素 | 内容 |
|---|---|
| マス | 正方形。間隔は2pt。詰めるほど「量」が伝わる |
| 中身 | 写真。無ければ生育段階の色とシンボル |
| 左下 | 日付（「8/31」）。**株ごとの「N日目」ではない**——日記は全体で一つなので、複数の株が混ざると何の日数か分からなくなる |
| 右下 | 本人が書いたものには鉛筆の印 |

**写真が無くても成立させる。**生育段階ごとに色を割り当て、発芽の淡い緑から開花の黄、枯死のくすんだ茶へと移る。**グリッドを俯瞰すると一生の弧が色で見える。**

| 段階 | 色 |
|---|---|
| 発芽 | 淡い黄緑 |
| 本葉 | 緑 |
| つぼみ | 濃い緑 |
| 開花 | 黄 |
| 結実 | 茶がかった黄 |
| 枯死 | くすんだ茶 |

**ただし色では区別できない対比がある。**「水切れ」と「その翌日の回復」は隣り合う本葉どうしで、同じ緑になる。**物語上いちばん劇的な対比なので、ここは写真が入って初めて意味を持つ**（しおれた葉 → 立ち直った葉）。

**お休みの日**は色を持たせず、明るい灰色に「お休み」とだけ置く。**書いた日が引き立つように、静かに沈める。**

**お休みが2日以上続いたら1枚にまとめる。**「お休み 3日 / 8/27〜8/29」のように範囲で示す。書かなかった日も残すという方針（D18-a）は保ちつつ、空白がグリッドを埋め尽くさないようにする。

| 操作 | 結果 |
|---|---|
| まとまりをタップ | 展開して個別の日が現れる |
| 展開した日を**ダブルタップ** | 畳んでまとまりに戻る |
| 展開した日をシングルタップ | その日の縦フィードへ |

**写真は枠に収める。**先に正方形を確定させ、そこへ画像を流し込んで切り抜く。画像側に大きさを決めさせると、縦長・横長の写真で枠が押し広げられ、**グリッドの行が崩れる。**同じ理由でフィードのカードも高さを固定する。

**今日はまとめない。**まだ書いていなくても、書く場所が要る。

**仕込みの日記は20日分ある。**timeline.json のパネルは8日分しかなく、そのままだと16日連続で空白になる区間ができ、実際に育てている人の日記に見えない。段階の変わり目ではない「ふつうの日」を12日分足し、**毎日は書かないが、そこそこ書く**という現実の粒度に寄せた。

**空状態**: 「まだ何も書かれていません。カメラを向けて、出会うところから」

### 5.1-a 縦フィード

マスをタップすると、**その日記を先頭にした縦スクロール**が開く。そのまま上下にスクロールすると前後の日記が続けて読める。

一覧に戻らずに流れで読めることが要点。グリッドは見渡すため、フィードは読むため。

| 要素 | 内容 |
|---|---|
| 見出し | 日付・N日目・生育段階。カードには両方出す。日付で位置が分かり、N日目で成長が分かる |
| 写真 | 観察時に撮ったもの。無ければ段階の色 |
| 本文 | **タップするとその場で書き換えられる。**保存の操作は要らない |
| そのとき植物が言ったこと | 引用として添える |
| 「+」ボタン | 見出しの右。写真を足す。上限に達すると「5枚まで」に変わる |
| 写真 | 左右にスワイプ。2枚以上なら下に位置を示す点を並べる |

### 5.2 書く

右上の「+」から。

| 要素 | 内容 |
|---|---|
| 写真 | 観察の記録から選ぶ。展示では仕込みの写真から |
| 本文 | 複数行のテキスト |
| デコレーション | スタンプ・テープ風の飾り（D26） |
| 保存 | セッション中のみ保持。リセットで消える（D36） |

**絵日記らしさは様式で作る。**手書き風フォント、紙のテクスチャ、マスキングテープ風の枠。AI生成のイラストは使わない——生成された絵は「自分の植物」ではなく、振り返ったときに感情が乗らない。

### 5.3 自動生成モード

切り替えで、観察のたびに植物の一人称で日記が綴られる。

**展示では既定でオンにする。**来場者は数分しか触らないため、自分で書く時間がない。すでに書かれたものが並んでいる状態を見せる。

## 8-a. 仕込みの株の位置づけ

**仕込みの株（ひまり）は選択中にしない。**来場者の株と混ざらないようにするため。

**D40-a により、未選択のあいだカメラは「見当たらないなぁ」になる。**ここから進む道は2つ——弧（D39）でひまりを選んで観察するか、「迎える」で自分の株を迎えるか。どちらも自分で選ぶ操作になる。

| 株 | 位置づけ | リセット時 |
|---|---|---|
| ひまり（仕込み） | 開発者が3ヶ月育て、看取った記録 | **残る** |
| 来場者が登録した株 | その場で「はじめまして」から始まる | **消える** |

これにより、来場者は**他人が育てた一生分の記録を見てから、自分でも1株を始める**という流れになる。セクション1で伝えたい「時間が積み上がる」が、アプリの中で直接見える。

仕込みの株は枯死まで到達している。**一生分の記録が見られること自体が、企画の到達点（D18-a）を伝える。**枯れた株には現在進行形の文言を使わない（「一緒にいて78日」ではなく「78日を共に過ごしました」）。

## 8-b. 写真の調達が critical path に乗った

**3列グリッドは写真の質がそのまま画面の質になる。**カード表示なら本文が主役なので写真が弱くても成立するが、グリッドは写真しか映らない。

展示までに、ひまりの成長を撮った**8枚**が要る。

| 必要な写真 | 対応する日 |
|---|---|
| 発芽 | 6日目 |
| 本葉が出た | 14日目 |
| **水切れ（しおれた葉）** | 23日目 |
| **回復（立ち直った葉）** | 24日目 |
| つぼみ | 38日目 |
| 開花 | 45日目 |
| 結実 | 62日目 |
| 枯死 | 78日目 |

**23日目と24日目の対比が最も重要。**色では区別できず、写真でしか伝わらない。ここが「お世話が効いた」ことを示す唯一の視覚的証拠になる。

これらは時系列パネル（D33 セクション3）にも使えるため、**撮影は一度で両方をまかなえる。**
