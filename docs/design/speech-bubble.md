# 吹き出しの設計

セリフの吹き出しを、**何で描き、どこへ置くか**を決める。

最終更新: 2026-09-20
状態: **実装済み**（D49 / D50 / D50-a / D51）。数値の詰めは実機待ち

## 1. この文書が扱う問題

吹き出しはこのプロダクトの主役（D2）だが、2つの問題を抱えていた。

| # | 問題 | 何が起きていたか |
|---|---|---|
| 1 | 紙に見える | 白のべた塗りで、後ろの植物を隠していた |
| 2 | **指す先が定まらない** | 手ぶれで先端の向きが揺れ、どの株の言葉なのか読み取れない |
| 3 | **居場所が悪い** | 株の真上に置いていたので頭を隠し、株が画面の上寄りにいると画面の外へ出る |

2は見た目の調整では解けない。**原因が3つあり、どれも別の場所にあった。**

3は、2を解いたあとに残った問題。**優先順位が違っていた**（D50）。
大事なのは尻尾が正確に指すことではなく、**吹き出し自体が常に適切な位置に
あり続けること。**先に本体の置き場所を決め、尻尾は後から本体と株を繋ぐ役に回る。

## 2. 見た目 — 半透明の風船

### 2.1 何に寄せるか

**紙の吹き出しではなく、半透明でポップな風船。**後ろの植物が透けるので、
実物を主役から降ろさずに済む（原則1）。写実には寄せない。映り込みを増やすほど
絵としての軽さが消え、カメラ映像の一部に見えてくる。

### 2.2 ぼかしの素材は使えない

`Material` / `UIVisualEffectView` は **ARKit が Metal で描くカメラ映像を取り込めない。**
素材を置いても地の色が出るだけで、背景が変わっても見え方が動かない。
これは弧（`PlantSelectorArc`）で先に分かっていた制約で、吹き出しにも同じく当てはまる。

**白の重なりと艶で自前で作る。**

| 層 | 中身 |
|---|---|
| 地 | 白の線形グラデーション（左上が濃く、右下が薄い） |
| 内側の照り | 輪郭をぼかして内側に落とした光。面が丸いことはここで伝わる |
| **反射** | **輪郭をなぞる光の筋。**左上に長いのと短いのを1本ずつ、右下に1本。**3本まで** |
| 縁 | 白のグラデーションの細い線。上ほど明るい |
| 影 | 広い影と狭い影の2枚。合成してから落とす |

**反射は縁に沿って走らせる。**ぼかした塊を中ほどに置く描き方では、
平らな板に汚れが乗ったようにしか見えなかった。丸い面に映り込む光は輪郭をなぞるので、
角の丸みに沿わせると一目で風船に見える。**短い1本は少し離して置く。**
続けて引くと、ただの太い縁取りになる。

増やすのは3本まで。増やすほど写実に寄っていき、絵としての軽さが消える。

### 2.3 地の濃さは明るさで決める

`ambientBrightness`（ARKit の実測値）で 0.66〜0.86 の範囲を動かす。
**明るい部屋ほど濃くする。**薄いままだと、明るい背景に黒い文字が負ける。
弧と同じ値を見ているので、画面の中で明暗が揃う。

### 2.4 幅は文字を測ってから決める

`frame(maxWidth:)` では短いセリフにも上限いっぱいの風船が付く
（最大幅の枠は、提案された幅をそのまま取るため）。`BubbleMetrics.textWidth(for:)` で
実寸を測り、上限 250pt で折り返す。**「……」には小さな風船が付く。**

## 3. 置き場所（D50）

### 3.1 空間の点を2つ持つ

| 点 | 何を表すか | 使い道 |
|---|---|---|
| 株の点 | 葉の塊の中ほど | しっぽが指す先 |
| 本体の点 | 株から斜めにずらした位置 | 本体の置き場所 |

**どちらも空間に固定して毎フレーム投影する。**2つとも固定だから、
全体が空間の中で1つの物として動く。本体だけ画面で決めると、
端末を動かすたびに吹き出しだけが遅れて付いてきて、**板に貼った字幕に見える。**

### 3.2 株の斜めに置く

**真上には置かない。**株の頭を隠すし、株が画面の上寄りにいると本体が画面の外へ出る。
左上・右上・左下・右下の4つから選ぶ。

置き場所そのものは、**株の枠からの相対だけ**で決まる。

```
本体の中心 = 株の枠の角 ∓（本体の半分 − 本体 × 0.28）
```

食い込みの 0.28 が唯一の調整代になる。小さくすると株から離れ、
株が大きく写っているときに画面の外へ出ていく。

### 3.3 画面を見てよいのは、象限を選ぶときだけ

4つの候補は株に対して対称に並ぶので、「株を隠す割合」も「株からの距離」も
どれも同じ。**選ぶ材料になるのは、いま見えている画面のどこに落ちるかだけ。**

| 項目 | 重み | 中身 |
|---|---|---|
| 置いてよい範囲から出る | ×3 | 安全領域と下端の操作を除いた矩形から出る割合 |
| 株のいる側 | ×1.2 | **株が画面の右寄りなら左、左寄りなら右** |
| 上に置く | −0.25 | 漫画の記法に沿うし、画面の下端は操作で埋まっている |

**ここでだけ画面を見てよい。打つ瞬間の1回きりだから。**

置いてよい範囲は**収める枠ではない。**収めてしまうと、株に対する位置が
画面の都合で変わる。それは次の判定にそのまま効いて、**端末を振るたびに
吹き出しが画面へ戻ってくる。**

### 3.4 ずれたときだけ置き直す

**「画面から出そうか」で判定してはいけない。**端末を振れば吹き出しは画面の端へ
寄るので、振るたびに打ち直して画面へ戻ることになる。それは空間に固定されている
とは言わない。**カメラを株から外せば見えなくなってよい。**

大事なのは、**株に向けたときに株に対して適切な位置にあること。**

本体の点は打った瞬間の3D位置に固定されるが、次の2つでずれていく。

- **株の点が直り続ける**（§5 の寄せ直し）。本体は置いたままなので、2点の関係が少しずつ変わる
- **株の周りを回り込む。**ずらした向きは打った時点のカメラ基準なので、角度が変わると、
  斜めに置いたはずの吹き出しが株の真上や裏に見える

どちらも「いま見えている株の枠から計算した、あるべき位置」との差に出る。

| 条件 | しきい値 |
|---|---|
| あるべき位置から離れた | 本体の大きさの 0.5 倍 |
| 株に被った | 株の枠の35%超 |

**乗り換えを渋る。**ずれた状態が 1.5 秒続き、かつ前に動かしてから 4 秒以上
経っているときだけ動かす。見直し自体も 0.3 秒おき。

**置き直しはなめらかに移動する**（時定数 0.18 秒）。消して出し直すと、
セリフを読んでいる途中で途切れる。**移っているあいだだけ空間固定が崩れる。**

### 3.5 しっぽ

**先端を株に重ねに行かない。**長さは変えず、向きだけを株へ寄せる。

| 本体の位置 | 生える辺 | 付け根 | 向き |
|---|---|---|---|
| 左上 | 下辺 | 右寄り | 右下へ |
| 右上 | 下辺 | 左寄り | 左下へ |
| 左下 | 上辺 | 右寄り | 右上へ |
| 右下 | 上辺 | 左寄り | 左上へ |

辺は株が本体の上下どちらにいるかで決まり、付け根は株の横位置をそのまま辺に写す
（角の丸みに掛かる手前で止める）。向きは**辺の垂直から 15〜45°** に制限する。
**正確さより形の安定を取る。**下限が要るのは、斜めに置いてあるのに真下を向くと
株を指していないように見えるため。

**寝かせるほど縦の伸びが減って寸詰まりに見える**ので、長さを最大22%足し、
付け根を最大18%狭めて、どの角度でも同じ物に見えるようにしてある。

### 3.6 形

**尖らせない。細く長いしっぽは矢印になり、指した先のずれがそのまま目に付く。**
付け根 34pt・長さ 21pt と、長さより幅を広く取る。

形は3つの決めごとでできている。どれも、崩すと別の物に見える。

| 決めごと | 値 | 崩すとどう見えるか |
|---|---|---|
| **付け根は辺と同じ向き（水平）で出る** | 水平を保つ長さ＝付け根の幅の0.30 | 角が立ち、板を貼り足したように見える |
| **側面は緩やかな曲線** | 3次曲線1本。両端の向きだけ決める | 直線だと、丸い風船に硬い三角が付く |
| **先端の円に、斜めから接する** | 真横から38° | 真横で受けると、そこから先が同じ太さの茎になり、**蛇口から垂れたように見える** |

先端は半径 2.5pt の円で受ける。側面はこの円に接するので、継ぎ目に角が出ない。

**傾けても、図形ごと回さない。**付け根が辺から浮き、せっかくの繋ぎ目の丸みが壊れる。
付け根は辺の上に残したまま、先端の向きだけを変える。

**付け根は角の丸みに掛からないところまで狭める**（`min(34/2, 幅/2 − 角の丸み)`）。
掛かると、向きを合わせる相手（辺の直線）が無くなる。「……」のような小さな風船では、
しっぽもそのぶん細くなる。

**本体としっぽは1つの図形に合成する**（`Path.union`）。2つの図形のまま重ねると、
縁の光が本体の辺をしっぽの付け根に横切って引き、**継ぎ目が線として出る。**
地が半透明なので、上から重ねて隠すこともできない。

## 4. 震えを取る

### 4.1 一定の係数では解けない

以前は前の値へ 0.25 ずつ寄せていた。**震えを消すほど追従が遅れ、
追従を上げるほど震えが残る。**どちらか片方しか取れない。

### 4.2 1€ フィルタ

**動きの速さから、均しの強さを毎フレーム決める**（Casiez et al., 2012）。

| 状況 | ふるまい |
|---|---|
| ほとんど動いていない | 強く均す。手ぶれの震えが消える |
| 速く動いている | ほとんど均さない。向けた先にすぐ追いつく |

| 定数 | 値 | 意味 |
|---|---|---|
| `minCutoff` | 0.8 Hz | 止まっているときの強さ。小さいほど強く均す |
| `beta` | 0.010 | 速さに応じて追従を上げる度合い |
| `derivativeCutoff` | 1.0 Hz | 速さそのものを均す強さ |

経過時間（`dt`）を使うので、**フレームレートが落ちる端末でも追従の速さが揃う。**

### 4.3 不感帯

フィルタを通しても最後の1ptは揺れ続ける。**1.2pt 以下の動きは配らない。**
止まっているときは本当に止まる。`@Observable` の配り先が毎フレーム組み直されるのも防げる。

### 4.4 投影した点にアニメーションを掛けない

`CameraTab` で `.animation(.spring, value: bubbleScreenPoint)` を掛けていた。
**毎フレーム更新される値にバネを掛けると、追いつく前に次の目標が来る。**
吹き出しは遅れて泳ぎ、止まった瞬間には行き過ぎて戻る。外した。
震えの始末はフィルタが受け持つ。

### 4.5 大きさは株の見かけの大きさで決める（D50-a）

```
1行ぶんの本体の高さ ＝ 株の枠の（幅＋高さ）÷2 × 0.25
```

**距離ではなく株に繋ぐ。**はじめは距離に反比例させていたが、株の大きさを見ていなかった。
**小さい株ほど近くに寄って見る**ので、小さい株ほど倍率が上がり、株に対して吹き出しが大きくなる。

株の見かけ自体が距離に反比例するため、**「遠ざければ小さく」はこの式のまま成り立つ。**
等倍になる距離という概念が要らなくなった。

| | 値 | 理由 |
|---|---|---|
| 比 | 0.25 | 理想の見本の実測（本体 388×96px / 株 405×358px）。**実機で詰める** |
| 基準 | 1行ぶんの本体の高さ | 本体そのものだと、2行のセリフだけ文字が小さくなる |
| 株の大きさ | 幅と高さの平均 | 高さだけだと横に広がった株で、幅だけだと背の高い一本茶で小さくなる |
| 近いほうの上限 | 本体の幅が画面の85% | 倍率で止めると長いセリフだけ切れる |
| 遠いほうの下限 | 0.3倍 | これ以下は点にしか見えない |

**遠くで読めなくなるのは、そのままにする。**読めないこと自体が「近づいてみて」という誘いになる。

**入口の値は、どうしても段になる。**

| 段の出どころ | 何が起きるか |
|---|---|
| 株の枠は**1.2秒ごと**にしか測り直さない | そのたびに基準が跳ねる |
| 距離は **0.02m 刻み**でしか配っていない | 0.8m で 2.5%、見て分かる段になる |

ふたつとも別々に均すのではなく、**出口でまとめて飲み込む。**

- 目標の倍率を毎フレーム計算し、**時定数 0.2 秒でそこへ寄せる**（`advanceScale`）。
  入口がどう跳ねても、出てくる大きさはなめらかになる
- 距離は、配る値（`anchorDistance`、段あり）と**計算に使う値（`liveDistance`、段なし）を分ける。**
  段は診断表示が毎フレーム組み直されるのを防ぐためのもので、大きさの計算には要らない
- 株の枠を混ぜる係数は **0.15**。株の実際の大きさは変わらないので、
  測り直しは雑音の訂正でしかない。強く混ぜるほど跳ねる

**跳ばしてよい場面は2つだけ。**初めて株を測ったとき（寄せていくと出た直後に膨らんで見える）と、
セリフが変わったとき（吹き出しがどのみち出直す）。

**刻みは要らない。**本体の中心は投影点そのもので、拡大縮小しても中心が動かない。

## 5. 打った点そのものを正す

震えを取っても、**打った点が間違っていれば吹き出しは株から離れる。**
原因が2つあった。

### 5.1 奥行きが取れないとき、画面の中央に打っていた

レイキャストが外れたときは固定距離 1.2m に落とす（D3-a）。
その落とし先が**カメラの正面方向**だった。株が画面のどこに写っていても、
打たれる点は画面の中央。

植物は平面検出が最も苦手な被写体で（D3）、外れる回は多い。
**吹き出しが株から離れて見える一番の原因がこれだった。**

**その点を通る視線の上に置く**（`ARView.ray(through:)`）よう直した。

### 5.2 一度打った点を、二度と直していなかった

相手が決まると検出を止めていたため、最初の1回で決まった点を使い続けていた。

**奥行きを外したときの取り返しが効かない。**1.2m のつもりで打った点が本当は
0.5m のところにあると、端末がわずかに動いただけで**見かけの位置が大きくずれる。**
手ぶれで吹き出しが泳いで見える原因は、姿勢推定の震えよりこの視差のほうが大きい。

**相手が決まったあとも検出を走らせ、点を寄せ直す**（`refineAnchor`）。

| 決めごと | 値 | 理由 |
|---|---|---|
| 間隔 | 1.2秒以上 | 探すときより空ける。位置を直すだけなので頻度は要らない |
| 混ぜる割合 | 0.25 | **飛びつかない。**1回の結果をそのまま採ると、隣の鉢や通りがかりの人を拾った拍子に持って行かれる |
| 捨てる距離 | 0.5m 超 | 遠い結果は別のものと見なす |
| 奥行きが取れないとき | **向きだけ直し、距離は変えない** | 固定距離に落とすと、当たっていた奥行きを毎回押し戻す |

パネル（画像アンカー）はこの経路を通らない。位置は ARKit が持っている。

## 6. 座標系

吹き出しの点は `ARView` の**画面いっぱいの座標系**で来る。重ねる側も
`.ignoresSafeArea()` を掛けて同じ座標系に揃える。掛けないと、
**ノッチのぶんだけ下にずれて植物から離れる。**キーボードで持ち上がらないのも同じ理由。

## 7. いつ出すか（D51）

**検出できた瞬間には出さない。**面積の下限が 3% しかなく、
**株が画面の端にちらっと入っただけで成立していた。**来場者から見ると、
まだ株を見ていないのに話しかけられる。

| 条件 | 前 | いま |
|---|---|---|
| 植物らしさ | 0.10 以上 | 変えない |
| 面積 | 画面の 3% | **画面の 4%**（雑音よけの床。ここでは測らない） |
| 位置 | なし | **枠がどの辺でも切れていない＝株の全体が入っている** |
| 続けて | なし | **0.3秒** |

**面積では測らない。**一度 12% まで上げたところ、**株に限りなく近づかないと出なくなった。**
面積は「どれだけ大きく写っているか」の話で、「捉えたか」とは別物。
**遠くても、全体が入っていればそれでよい。**

枠が画面の端に貼り付いているかで「全体が入っているか」を見る。マスクの枠は画面で切られるので、
辺に接していれば、そこから外へ続いていると分かる。**切れてよいのは1辺まで**——
鉢の足元や、葉先が1枚画面の端に届いた程度では落とさない。
厳しさは診断パネルで切り替えられる（全体 / 1辺可 / 問わない）。

**取りこぼしを1回は許す。**許さないと、成立には**間隔ぶん空けた検出を2回連続で完璧に
通す**ことが要る。検出の間隔は処理時間の3倍（0.4〜2.0秒）なので、マスクが半分の確率で
しか安定しないだけで数秒〜十数秒かかる。**探しているあいだは間隔も 0.6 秒までに詰める**——
吹き出しが出ていないので、守るべき追従が無い。

**どの条件で落ちたかを診断パネルに出す**（らしさ／面積／収まり）。
見えないと、推測で数値をいじることになる。

**アンカーは最初に条件を満たした時点で打つ。ただし見せない。**待っているあいだに
寄せ直し（§5）が効くので、**出た瞬間から正しい位置に居られる。**

**実際に出るまでの時間は、検出の間隔に律速される。**探している間の間隔は 0.4〜0.6 秒なので、
0.3 秒という設定は実質「次の検出でも条件を満たすこと」を意味する。

**成立と同時に、触覚（`pulse`）と一言目を出す。**検知は目に見えない出来事なので、
そこで鳴らすと何の合図か分からない（H-3）。

**「はじめまして」（シャッターの「迎える」）は待たない。**「話しかける」を押した直後なので、
待つと押した手応えが消える。パネルもこれまで通り即座に出す。

## 8. 実機で確かめること

### 震えと追従（D49）

- **手ぶれの残り方。**`minCutoff`（0.8Hz）と `beta`（0.010）の詰めは実機でしか決まらない
- **寄せ直しの効き。**`refineBlend`（0.25）が小さすぎると直りきらず、大きすぎると持って行かれる

### 置き場所（D50）

- **象限の切り替えが起きすぎないか。**判定材料になる株の枠は**検出が1.2秒ごとにしか
  更新しない**ので、切り替えは最大1.2秒遅れる。実害が出るかは実機で見る
- **本体の点は、置いた時点のカメラの右／上を基準に株からずらす。**
  株の周りを大きく回り込むと、ずらした向きが意味を失う。置き直しの条件に掛かるはずだが未確認
- **近づくと画面からはみ出す。**株の見かけも本体も距離に反比例して大きくなるので、
  「株＋吹き出し」の並びは**距離によらず同じ形**のまま拡大する。株が画面いっぱいに写る
  距離まで寄れば、その並びは画面に入らない。**画面に収める寄せはしない**と決めた以上
  （§3.4）、寄りすぎたときは端から出る。実機でどこまで気になるか見る
- **「なめらかに移動」の 0.18 秒が、空間固定の崩れとして気になるか**
- 置いてよい範囲の余白（上72 / 左右16 / 下168）が、実機のシャッターと弧に合っているか

### 大きさ（D50-a）

- **比 0.25。**見本で測ったのは葉だけだが、**検出が返す枠は鉢まで含む可能性が高い。**
  そのぶん枠が縦に伸びるので、係数を下げる必要があるかもしれない。診断パネルにスライダーあり
- 0.3倍まで縮んだときに「何か言っている」と伝わるか、ただのゴミに見えるか
- **縦持ちの画面は狭い。**9文字のセリフはこの大きさで画面幅の61%を占めるため
  （見本の square な画面では38%）、株が画面の中ほどにいると横に並べる余地が残らない。
  **文字の折り返し幅（いま250pt）を狭めるのが次の手**

### 検知（D51）

- **「落ちた条件」を見る。**らしさ／面積／収まりのどれで弾かれているかで、直す先が決まる
- **前景マスクが机や床まで拾わないか。**拾うと枠は常に下端で切れる。「枠の収まり」で
  どの辺が切れているか見える。2辺以上切れ続けるなら「問わない」に落とす
- 取りこぼしを1回許してなお成立が遅いなら、`allowedMisses` を増やす
- 0.3秒（実際は検出の間隔ぶん、0.4〜0.6秒）が、ちょうどよい間になるか
- **遠くから成立したとき、吹き出しが小さすぎないか。**全体が入っていれば遠くても成立するので、
  倍率の下限（0.3倍）に張り付く場面が出る

### 見た目

- 地の濃さと反射の強さが、明るい窓際と暗い部屋の両方で成立するか
