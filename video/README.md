# video — 紹介動画

アプリの**操作の感じ**を伝える動画。30fps。[Remotion](https://www.remotion.dev/)（React で動画を組む道具）で作る。

| 版 | コンポジション | 大きさ | 長さ | 中身 | 音 |
|---|---|---|---|---|---|
| 長い版・縦 | `TourLong` | 1080×1920 | 1分40秒 | **カメラから始め、「出会う → 話す → 記録する → 共有する」の流れで見せる。**注目する場所へ寄る。上から章の線・語り手・案内役・端末 | BGM・効果音 |
| 長い版・横 | `TourLongWide` | 1920×1080 | 1分40秒 | 縦と同じ構成。左に章（縦に並ぶ丸と線・いまの章は大きく）、中央より少し左に端末、右上に語り手（右詰め・白いモヤと文字の影）、右下に案内役 | BGM・効果音 |
| 30秒版 | `Tour` | 1080×1920 | 約31秒 | マイプラント・日記・トーク・プロフィールの操作だけ | なし |

縦と横は**台本・時間・寄り先が共通**で、置き場所だけが違う（`src/long/layout.ts`）。

## 作り方の全体

```
DemoTourTests（UIテスト）       ─ 台本どおりに画面を操作する
   ＋ -showTouches YES           ─ アプリ自身が指の位置に丸を描く
   ＋ -demoCamera <写真>          ─ カメラの映像の代わりに写真を映す（カメラの台本だけ）
        │
xcrun simctl io recordVideo      ─ シミュレータの画面を録画する
        │  npm run record [-- camera | flipbook]
        ▼
public/tour.mp4                  ─ 各タブの操作（約84秒・待ち時間を含む）
public/camera.mp4                ─ カメラ（約76秒）
public/flipbook.mp4              ─ ひまりのパラパラ（約24秒）
        │
src/long/cuts.ts                 ─ 録画のどこを使うか・どこへ寄るか・どこで音を鳴らすか・一言
        │  npm run render:long / render:wide
        ▼
out/plavo-tour-long.mp4          ─ 完成品（縦）
out/plavo-tour-wide.mp4          ─ 完成品（横）
```

## 手順

```bash
cd video
npm install

# 0. BGM を入れる（初回だけ・下の「音」を参照）
#    public/audio/morning.mp3

# 1. 録画を撮る（それぞれビルド込みで2〜3分）
npm run record              # 各タブ → public/tour.mp4
npm run record -- camera    # カメラ → public/camera.mp4
npm run record -- flipbook  # パラパラ → public/flipbook.mp4

# 2. 切り出しを録画に合わせる（撮り直したときだけ）
#    長い版は src/long/cuts.ts（縦横共通）、30秒版は src/cuts.ts の秒を直す。Studio で見ながら直すと早い
npm run studio

# 3. 書き出す
npm run render:long   # 縦 → out/plavo-tour-long.mp4（5分ほど）
npm run render:wide   # 横 → out/plavo-tour-wide.mp4（5分ほど）
npm run render        # 30秒版 → out/plavo-tour.mp4
```

`npm run record` は iPhone 17 のシミュレータを使う。別の端末にするなら `DEVICE_ID=<UDID> npm run record`。ただし画面の大きさ（402×874pt）が変わると、台本の位置と動画の端末の縦横比がずれる。

効果音を作り直すときは `npm run sfx`（`public/sfx/`）。

## 長い版の構成

章は **BGM の小節の頭**から始まる（約118 BPM・1小節約2.04秒・`src/long/timeline.ts`）。はじめは60秒だったが、速くて目線が追いつかないので1分30秒にし、センサーの場面を足して1分40秒にした。

**章の長さに足りないぶんは、切り出しを伸ばして埋める。**まず次の切り出しとのあいだ（録画から切り取っていた待ち時間や文字の入力）を戻す。録画のとおりに続くのでつなぎ目は増えない。それでも足りなければ、各切り出しの最後のコマで少しずつ止める。スローにはしない（画面の動きが間延びする）。

| 時間 | 章 | 見せるもの |
|---|---|---|
| 0:00〜 | — | タイトルの背景（ロゴを消したもの）に「Plavoアプリ紹介動画！☘️」（約4秒・縦は2行） |
| 0:04〜 | 出会う | ぼけたカメラ → シャッターを「迎える」へ → 「この子でいい？」→ 名前「まる」→ 話しかけてくる |
| 0:22〜 | 話す | 「お水欲しいな」→ 水（しずく）→「気持ち良い！ありがとう」→「もう少しだけ日向ぼっこしたい」→ 日向（太陽・光の筋）→「あったかい、ありがとう」→ **センサーを鉢に刺す → 右端のつまみを引いてセンサーの値を見る（D64）** → 撮る → 左下の1枚 |
| 0:53〜 | 記録する | マイプラント → 育成のグラフ → ギャラリー → ひまりの一生をパラパラで |
| 1:07〜 | 共有する | 日記（自分・友達・みんな）→ スタンプ 🌸 → ダブルタップで ❤️ → 家族のトーク |
| 1:30〜 | — | 6つの画面（センサーの値・育成・パラパラ／日記・トーク・プロフィール）を並べて引く |
| 1:36〜 | — | アプリのタイトルの絵（TitleScreen・ロゴ入り・4秒・文字は足さない） |

「話す」の切り出しの区切りは、録画の中でセリフが変わる時刻（約4秒おき）に合わせてある。ずれると、語り手とキャラクターの一言が画面のセリフと食い違う。

**一言は2人で分ける。**語り手（`narration`）は使い方の説明（「新しい子を、迎えましょう。」）、案内役のキャラクター（`comments`）は植物の気持ちの代弁や感想（「どんな子かな？」「お水をあげると、うれしそう」）。どちらも `src/long/cuts.ts` に書く。

- 語り手の一言は**切り出しごと**に書く。同じ一言が続くあいだは出し直さない。`\n` で改行できる（「写真や動画を、\n振り返ることができます。」）
- キャラクターの一言は**動画の秒**（出す・消す）で書く。切り出しの区切りをまたいで、画面のセリフや操作に合わせて出したいため。一覧に無い時間は黙って立っている。**切り出しや章の長さを変えたら、秒も見直す**

折り返しは文節で行う（`word-break: auto-phrase`）。

語り手の一言は枠を付けず、文字の下に白いモヤ（ぼかした白）を**行ごとに、その行の文字の長さだけ**敷き、文字にうっすら影を付ける（端末に重なっても読めるように）。一言が変わるたびに右から滑り込みながら出る。

**寄り**は切り出しごとに `zoom`（画面のポイントと倍率）で書く。**「やあ」〜「あったかい、ありがとう」の間は寄らない**（セリフのたびに寄り先が移ると、画面があちこちへ動いて見づらい）。撮るときは画面の下（シャッター・左下の枠）へ寄る。注目する点をキャンバスの中ほどへ運ぶ倍率と位置を寄り先ごとに決め、そのあいだを約1.3秒（40コマ）のゆるい加減速で移る。

- **拡大と移動を同じ進み方で動かす。**はじめは移動を拡大の途中で終わらせていたため、二段に動いて見えた
- **倍率は比で補間する**（1→2 の途中を √2 にする）。差で補間すると、寄り始めが遅く、寄り終わりが速く感じる
- 端末の縁はキャンバスの内側に入れない（注目する点が画面の端にあると、反対側に空きができるため）
- 寄りと寄りの間は40コマほど空ける。短いと前の寄りの途中で次が始まり、動きが途切れる

## カメラの場面（デモカメラ）

**ARKit はシミュレータで動かず、撮影に使える植物も手元にない。**そこでアプリに撮影用の「デモカメラ」を足した（`-demoCamera <写真のパス>`・`DemoCamera.swift`）。

- カメラの映像の代わりに**1枚の写真を手持ちのように揺らして映し**、株が選ばれていれば1秒で「見つけた」ことにする
- 作り物はこの2つ（映像と、見つけた判定）だけ。**吹き出し・シャッター・「迎える」・名前の入力・左下の1枚・弧はアプリの本物が動く**
- 揺れと株の位置は同じ式で画面に移すので、吹き出しは株に付いてくる
- 写真は [Pexels](https://www.pexels.com/photo/green-plant-with-white-ceramic-pot-1084188/) のホヤの鉢植え（Pexels のライセンス: 無料・商用可・クレジット不要）。カメラと同じ縦横比に切り抜いて `assets/camera-plant.jpg` に置いた
- 名前をつけたあとのセリフは**撮影用の台本で順番を決めてある**（`-demoScript YES`・`DemoCamera.script`）。普段はセリフ集の中からランダムに選ぶので、「……こわい」のような暗い一言が出ることがある。台本のセリフも**セリフ集にある本物**（無ければ落ちる）
- 日向ぼっこの場面では、アプリの側で映像を陰らせ、日向で明るく暖かくする（`DemoStage`）。「日が差した」ことは動画の側で絵にして重ねる（右上から顔を出す太陽・右上からにじむ暖かい光・斜めの光の筋）。はじめは光の筋だけで、気づきにくかった
- **センサーの場面（D64）**: 台本の最後にセンサーを鉢に刺す。センサーは参考画像（`reference/sensor_mock`）から Vision の前景の切り抜きで抜いたもの（`assets/sensor.png`・`-demoSensor`）。上から降りてきて、鉢のふちから下は隠れる（土に刺さって見える）。刺さったところで、アプリが Mac の中継サーバー（`server` の `npm run sensor`）から値を取り始め、ガジェットをまるに結ぶ。値は `server` のモックのガジェットが送る（水をあげた直後の72%・日向の18,000 lx・気温や湿度は毎回少し揺れる）。どちらも `npm run record -- camera` が立ち上げて、終わったら止める。**起動した直後には繋がない**（届いた水分で台本の値が上書きされ、株の自動選択も動くため）
- 動画ではカメラの場面に「※ カメラの映像はイメージです」と出す

関係する起動引数は [ios/README.md](../ios/README.md) にある。

## 判断したこと

### 指の跡はアプリの側で描く

シミュレータの録画には指が映らない。はじめは台本から押した時刻と位置を書き出し、Remotion の側で丸を重ねようとした。ところが **simctl の録画の時刻は壁時計から少しずつずれ**（始めは約0.4秒、30秒ほどで約2秒。一定でない）、押した瞬間と丸が合わなかった。アプリの側で描けば、指の跡も画面と同じ録画に入り、ずれようがない。

### 待ちの間で切る

UIテストは操作のたびにアプリが落ち着くのを待つので、録画には止まった時間が多い。**画面が止まっている間で切れば、つなぎ目は見えない。**そのため切り出しは細かく分けてある。

### ピンチは写真1枚の上で

画面全体に向けてピンチすると、片方の指がタブバーに乗り、指を寄せる動きでタブの選択を引っ張ってしまった（プロフィールからトークへ移った）。中央の写真の上でつまむ。

XCUITest のピンチは勢いが付き、大きくつまむと3列から10列近くまで進む。控えめにゆっくり1回だけつまむ（`scale: 0.6, velocity: -0.8`）。

### 水やりと日向は台本で起こす

展示では水やりは説明員の隠し操作（モック）、日向は株を動かすことで起きる。動画ではどちらも見せられないので、名前をつけてからの時間で起こす（`DemoCamera.script`）。土の水分は「水が足りない」（15%）から「水をあげた直後」（72%）へ移す。台本のあいだは土を乾かさない。乾いて帯域が変わると、台本と別のセリフに差し替わる（はじめはこれで「……こわい」まで落ちていた）。

### 横画面の案内役はオリジナルで描く

「Duolingo 風の女性のキャラクター」という依頼から始まった。**既存のキャラクター（Duolingo の Lily など）の見た目は写さない**（権利の問題になる）。はじめは女性の人物を描いたが、ユーザーから参考画像（黒い丸に目だけ・青い丸い三角に大きな目と口）を示され、**シンプルな形**に改めた。

いまは緑の丸い三角のからだに、大きな目と小さな口、頭に双葉を1つのせた形（`Presenter.tsx`）。目は吹き出しのある左上を見る。待機中はゆっくり弾み（足もとの影も伸び縮み）、3.4秒ごとにまばたきし、双葉が揺れる。一言が変わると、吹き出しが出直し、口が1秒ほど開いたり閉じたりする。
